## 4. 拟执行顺序与命令类别

以下是待批准的命令方案，不是本轮执行记录。精确工具绝对路径与验证目录应在执行前记录，不能盲用全局工具。

1. 只读核Git、白名单POM/package/lock和许可；冻结实际文件清单及工具版本。管理端现有脚本包括`pnpm ts:check`、`pnpm build:prod`和`pnpm lint`，原环境构建会读取配置，禁止未审直接运行。
2. 先重现AV1隔离副本，再对最小适配改动做前后对照；沿用原锁的安装建议`pnpm install --frozen-lockfile`，依赖生命周期脚本与下载来源须先审。安装不能被“本地构建”授权隐含覆盖。
3. Java只对获准白名单副本运行有效POM、依赖树及编译；沿用既有脚本的模块和处理器约定。拟用`mvn help:effective-pom`、`mvn dependency:tree`、`mvn -DskipTests compile`，具体profiles/repo参数以脚本核对结果为准。跳过测试的编译结果仅算编译证据。
4. 管理端在无秘密副本执行原类型/构建脚本。每项TS2304明确“修复”或“批准的首期编译边界排除”，均不能放宽全工程质量门槛。检查GB1产物引用及深链接，保留原源码。
5. 玩家空壳采用已确认候选Nuxt4.6.2/Node24.22.1/pnpm10.34.8，精确制品与锁文件形成后，拟执行类型检查与静态生成；具体命令由新package脚本固定。验证公开产物、私有空壳、未知路由真实404和无敏感数据；不接API。
6. 汇总证据并提交W00-A验收；列出W00-B阻塞和下一次账号/数据/SQL授权方案。未获B授权不连接服务。
