## 3. 首批必须细化的边界用例

| 组 | 精确边界与失败注入 | 必须满足 |
| --- | --- | --- |
| GP1交接 | 服务端计时的30分钟、15分钟、24小时各自前/恰好到期/后；登录响应丢失、旧guest撤销、双账号/会话、公开intentId、位置到期 | 采用规格的半开有效区间：当前时间达到expires_at即过期；同键同请求原结果，异请求拒绝；位置失效不抹付款、不自动重收费 |
| 产品GP1进度导入 | 兼容游客档/已有账号云档、邮箱未验证、跳过导入购买、确认后CAS变化/换号/版本变更、导入响应丢失 | 私人云档及导入前验证邮箱；玩家明确选择，保留双方、重新核并发与确认；失败保留来源，跳过不阻断购买，进度不授予权益 |
| EP1事件 | 72小时事件年龄、5分钟未来/开始边界；运行中与结束/撤会话、同键并发与异载荷 | 不用C延长W，不恢复run或会话；服务端现金与权益不受游戏观察事件影响 |
| 交易与升级 | 报价10分钟、账号/商品覆盖不一致、三重revision不同、重复通知、回跳取消、渠道超时、零补款 | 查证原订单/原渠道号；未知不当失败或再次扣款；来源守卫在同库事务内 |
| 存档与受控资源 | 不同账号、旧版本、CAS冲突、私有对象空/null版本、下载中撤权、超额分块 | 拒绝越权、保持冲突原文、实际字节与内存有界；存档不授权 |
| outbox与恢复 | 旧租约晚写、重认领、外部效果未知、限制尾部缺失、整库旧快照 | revision栅栏有效；查原结果而非换号重做；缺证范围停写隔离 |

精确错误码、字段和值以当前OpenAPI及各对象规格为准；若运行发现设计冲突，登记失败并提交变更，不自行降低验收。

## 4. 缺陷处理与发布退出

- 阻塞级：越权、金额/权益错误、数据损坏、无法恢复、核心流程不可用，立即阻塞相关里程碑与发布。
- 高优先：主路径失败、重复副作用、管理权限或数据口径严重错误，修复并回归后方可验收；不能靠标注“已知”放行。
- 一般问题：次要表现或有安全可用替代路径，记录影响、责任与处理计划，由用户明确接受遗留项。

不承诺未经确认的响应时限。缺陷需关联REQ/AC、工作包、测试、版本和修复提交，复测原失败并回归邻接信任链。上线前不得有未解决阻塞/高优先缺陷；剩余例外须真实批准。

发布门禁包含：构建和类型检查通过、适用AC逐项实测、双渠道真实条件与回调对账、来源/权限/存档隔离、完整游戏内容验收、监控/备份/恢复/回退证据、运行资源与访问许可、用户发布批准。当前均不因静态检查或本计划生成而通过。
