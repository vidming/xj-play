## 1. 使用与校验原则

以下数值是已确认的产品规格，不是观察到的负载、售价、游戏体量或团队产能。依赖支付渠道及资源可行性的项目后续实际核准，冲突须走变更确认。越界输入拒绝并定位字段，不能静默截断已售承诺、金额、存档或标识。

文本长度按 Unicode 码点计数，首尾空白去除后校验，正文允许换行。标识按精确值匹配；平台标识由可信平台分配，游戏不能自选任意账号。安全过滤不替代业务长度约束。密码不裁剪、不静默截断；具体邮件地址规范化和口令校验在认证设计中落实。

| --- | --- | --- | --- |

| 账号/退款/授予状态 | 只允许 PRD 2.4 及规则文档列出的业务语义 | 未知状态进入查证，不默认成功；无状态跳转默认值 | 不预定 API 枚举或数据库类型；账号身份/验证/生命周期分别表达 |
| 排序与分页 | 默认最新公开发布降序、稳定并列顺序；每页 12 项 | 无销量/评分数据不排序造榜；运营推荐单独标记 | 1 款也真实展示；失效页回到有效页并保留筛选，不凭空补满 |
| 统计区间 | 左闭右开，显式时区；默认最近 7 个完整自然日，可选 1–366 日 | 无跨币种合计；空分母“不适用”，未知费用不填 0 | 区间上限是查询产品规格，不是数据库/日志保留年限 |

金额始终以可信现金事实核对；超额收款作为异常事实保留，不能因大于输入上限就丢弃真实渠道结果。未来其他币种单独评审其最小单位，不以元/分模板处理。

## 2. 最小关联信息与状态组合

| 业务动作 | 最小关联信息 | 必须区分的状态/约束 |
| --- | --- | --- |
| 购买及交付 | 账号、游戏、商品承诺快照、币种、报价、订单、付款、权益来源 | 待付/未知/实收与待交付/有效/异常分开；账号与邮箱已验证不表示已购 |
| GP1 导入/保存/恢复 | 当前可信账号、作品、游戏版本/存档格式、来源、本次操作、预期目标修订、实际结果 | 读出/确认/写入/兼容恢复分别核对；云档变化重新选择；源数据保留；导入可跳过 |
| 升级及售后 | 合格来源付款与已退/在途、来源访问范围、报价、升级授予、本次实付、退款结论与执行结果 | 同现金来源只认列一次；原单关联不可丢；现金退款和撤权状态分开 |
| 免费授予 | 当前账号、已验证邮箱状态、作品、免费规则版本、授予来源 | 免费授予不是 0 元渠道付款；重复领取归同一业务事实 |
| 注销 | 当前账号重新识别、申请、处理范围版本、在途事项、最后确认、处理结果 | 同邮箱新账号不自动继承旧身份；删除和必要留存分别核对 |
| 发布/回退 | 作品/实际版本、商品范围版本、操作者权限、验证结果、发布尝试、前后状态 | 测试/预览与正式隔离；回退不倒改订单承诺或抹除存档兼容事实 |

平台只要求关联信息和可信结果，不规定游戏将剧情存成什么结构，也不要求 game payload 是 JSON。完整工程可由前端承载玩法；真实账号、付费范围及访问判定仍需平台可信服务。本阶段不选择托管、内嵌、SDK 或协议。

## 3. 统计通则

1. 报表展示 `Asia/Shanghai` 区间、生成时刻与“截至当前已核实结果”。日为本地 00:00 至次日 00:00，周为周一至下周一；不据此设定服务可用时长。
2. 发生期现金报表按可信付款/退款发生时刻归期，迟到核实进入原发生期的修订结果，并显示修订/核实时刻；历史导出保留导出时截点，不能静默当作同一版。
3. 支付、交付、保存、发布等成功率采用发起业务批次：分母为该期间被接受的去重业务对象，分子为同一批对象截至统计时刻的可信成功结果。展示成功/明确失败/处理中或未知/取消数量；之后成功会修订该批次，不改分母。失败后新业务操作是新对象，通信重试不是新对象。
4. 同时给“截至当前”和“已观察 24 小时批次”视图，年龄不足者单列；24 小时只是比较窗口，不是订单有效期、退款承诺或将未知置失败的期限。未知持续多久也不自动变失败；交易允许后续核实修订。
5. 浏览会话连续无活动 30 分钟结束；跨设备不猜同一人。同一可证会话内登录前后可关联同一发现链，分组标注“游客转账号”，不再分别算两次转化。不能把无法证实的访客与账号合并。
6. 测试/预览、运营验证与正式公开数据分别标记；全部指标默认排除测试。手动补偿/迁移有独立原因，不能拿补偿次数当新增购买量。
7. 分析事件用于观察，现金/权益仍以可信业务事实为准；缺参数和重复数据标记排除原因。每份操作取截至截点的核实结果，结果修订保留记录，不简单用“成功+失败”当全部请求。

## 4. 11 项指标的可复核定义

| 指标 | 去重单元、分母/分子与归期规则 | 未决与反例 |
| --- | --- | --- |
| M-01 发现到试玩 | 同一可证浏览会话+游戏为一单元；详情曝光作分母，本次详情之后、会话结束前的试玩就绪作分子；按详情发生期归组 | 没有详情来源的直达试玩另列，不除以全部详情；登录转换只算一次；未支持试玩作品独立列，不混入可试玩转化分母 |
| M-02 支付完成 | 有效支付意图的订单去重，不按点击/尝试计；同批核实完成付款订单/分母 | 同订单重试不增分母，未发起支付订单另列；零补款/免费不入分母；跨期成功回到原批次 |
| M-03 付费交付完整 | 已核实付款且应交付的订单为分母；全部应有范围可验证为分子，按付款发生期归组 | 部分交付不当全成功；后续退款另列售后，保留首次交付结果，不因退款倒改为未交付；零补款升级单列 |
| M-04 启动成功 | 获准启动的 run 为分母，对应游戏确认可交互为分子；试玩/免费/已购分组 | 授权拒绝进入 M-06，不入分母；取消/超时/未知单列，按钮点击不是就绪 |
| M-05 保存/恢复 | 有效云端保存操作和有效恢复操作分别为分母，对应核实完成为分子；GP 导入、自动/手动保存、恢复分别分组 | 本机保存不当云保存；通信重试不重复计；冲突待处理不当保存失败，恢复需游戏确认兼容 |
| M-06 异常 | 按独立业务对象+分类记录异常次数/影响操作数，不将重复错误消息当不同故障；核实越权事件另列 | 一个操作可能有多个原因，分类数不强求总和等于影响操作数；未授权成功泄漏需独立追踪，不能只看拒绝数 |
| M-07 发布质量 | 每个被受理的发布尝试为分母，该次实际生效为分子；按受理期归组 | 草稿保存不计发起；发布被拒后修订再提交是新尝试；后续回退/暂停另列，发布成功不表示游戏安全已全面证明 |
| M-08 售后负担 | 有效受理申请去重数/同期核实付款订单数；明示为工作量比值，可能大于 100%；另按订单批次列有售后订单数/该批已付订单数 | 同申请补材料不增；一单多个不同问题可多申请；退款成功与处理中、首次响应/总处理耗时分别列，按已确认SV1目标区分超期与待查证，不强迫结案 |
| M-09 金额 | 发生期已核实实收－成功退款－已核对费用，按游戏/币种分组；跨期关联原单 | 未知费用标暂计；零补款/免费/已计原款的抵扣不重复收入。对账调整/费用退还带方向单列，不篡改原付款事实 |
| M-10 账号处理 | 注册/验证/找回/注销分别以被接受 operation 为分母、该动作核实完成为分子；按受理期归组 | 不把找回邮件已发当密码已重置；不采明文邮箱，不能合并动作来造总成功率 |
| M-11 免费领取 | 每账号/游戏首次有效领取为一个业务；核实授予/受理数；按首次受理期归组 | 重复查询/重复领取不增；先前已授予的结果返回不是新的免费发行量；交付未知单列 |

耗时展示样本数、中位数及 P95；无成功样本显示无样本。这里只定义比较口径，不承诺性能阈值。人工响应/更新/处理目标按已确认SV1计算；不能把全部未结工单直接标为“超期”，不能将7日方案目标当作必须结案。

## 6. 阶段移交条件

FS1/DP1/SV1已实际确认，依据为[当前有效决策](../../03-架构/决策/当前有效决策.md)。本文件与[产品规格与政策](产品规格与政策-V1.0-提交稿.md)共同构成主PRD规格；原候选稿保留历史。

浏览器/设备支持矩阵、图片资源规格、加载及响应体验指标由UI阶段提出并确认；存档1 MiB的实现可行性、编码计量、数据隔离及清理机制由架构与测试核准。支付有效期、退款渠道能力、滥用防护与实际资源在相应阶段评估。它们是已分配阶段的细化任务，不是尚未确认FS数值，也不是已完成测量。不编造并发、可用性、RPO/RTO或性能结果。

本文件没有API、数据库类型、主键生成方式、供应商选择、运行容器、实际付款或上线结论。最终PRD整体验收仍待用户实际选择。

密码长度依据保存在[官方资料核查](../sources/数据保留与售后政策依据核查-20261024.md)，不是中国法定值。邮箱验证不自动作为每次密码登录的第二因素。
