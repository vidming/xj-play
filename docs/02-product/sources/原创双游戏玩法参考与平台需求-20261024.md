# 原创双游戏玩法参考与平台需求

- 研究与访问日期：2026-10-24（Asia/Shanghai）。
- 研究边界：3 款作品、4 个一手公开页面，仅核验玩法描述并提炼阶段一平台候选需求。
- 方法：调用网页搜索与访问工具后，因工具未返回可读正文，改用只读 HTTP 请求读取开发者官网与 Steam 商店开发者作品介绍，四个页面均返回 HTTP 200；未运行、试玩或通关这些游戏。没有采用媒体评测、玩家评论、用户标签或攻略作为玩法证据。
- 文档性质：供主代理处理范围、PRD 与表单时参考的研究输入，不是已经通过评审的需求、接入验证或游戏设计稿。

## 3. 已观察的描述与交互模式抽象

“已观察”指页面文字明确说明，不代表实际体验验证；“模式抽象”是本研究对描述的归纳，不是原作者给出的完整流程。

### 3.1 Orwell：调查材料与信息选择

**已观察描述：**开发者介绍玩家可接触网络信息、私人通信和文件，并审核哪些信息交给安全机构、哪些拒绝提供；介绍明确指出提供的信息会带来后果。来源：[S1](https://www.osmoticstudios.com/orwell-keeping-an-eye-on-you/)，访问日期 2026-10-24。

**模式抽象：**查阅材料 → 判断信息 → 选择提供或舍弃 → 面对信息选择带来的后果。该描述支持“信息处理本身就是交互”的方向，不证明任意具体分支规则、存档粒度或回退方式。[S1](https://www.osmoticstudios.com/orwell-keeping-an-eye-on-you/)

**对本项目的关联判断：**可用于思考 G-B 调查过程与 G-A 选择后果的入口说明。它不直接证明来电应答机制，也不要求平台实现资料筛选器或剧情分支引擎。

### 3.2 SIMULACRA：模拟手机内的探索、沟通与解谜

**已观察描述：**Steam 开发者介绍通过手机界面探索消息、邮件、相册及应用，与失踪者的朋友交流、拼合信息、恢复文件及损坏数据；Features 列出社交应用、浏览器、图像与文字解密，以及五种可能结局。来源：[S2](https://store.steampowered.com/app/712730/SIMULACRA/)，访问日期 2026-10-24。

**模式抽象：**探索模拟应用 → 阅读或沟通 → 拼合信息／解谜 → 继续调查。来源支持多结局的存在，未在上述描述中交代具体选择与结局之间的计算规则；不能据此生成本项目的分支结构。[S2](https://store.steampowered.com/app/712730/SIMULACRA/)

**对本项目的关联判断：**对 G-A 有“通信承载叙事”的参考意义，对 G-B 有“在多个虚构信息界面之间调查”的参考意义。该介绍不能直接证明 G-A 应采用真实电话、实时通话或特定来电玩法；游戏内浏览器也不能据此解释为玩家必须访问真实外部网站。

### 3.3 Her Story：关键词检索与非线性理解

**已观察描述：**官网说明作品围绕真人视频资料库展开非线性叙事；Steam 的 How does it work? 进一步明确，玩家输入检索词，观看包含这些词语的视频片段，拼合理解故事。来源：[S3](https://www.herstorygame.com/)、[S4](https://store.steampowered.com/app/368370/Her_Story/?l=english)，访问日期均为 2026-10-24。

**模式抽象：**输入关键词 → 查看命中片段 → 形成理解并继续检索。再次检索是对该交互的循环归纳；本轮资料不支持固定的解谜顺序、统一章节进度或“已看完多少就等于理解多少”的判断。[S3](https://www.herstorygame.com/)、[S4](https://store.steampowered.com/app/368370/Her_Story/?l=english)

**对本项目的关联判断：**可帮助说明 G-B 的主动调查属性；同时提示平台候选方案应允许“继续调查”这样的入口表达，而不是先把所有游戏都描述为线性章节阅读。具体词汇仍由未来原创作品确定。

## 4. 阶段一平台候选需求

本项目已确认 PG1 首发承接同账号兼容试玩进度，并已选 S1 声明支持的平台存档；下表“未核实”仅指参考作品的实际能力。对本项目不再重复询问是否需要承接，继续设计具体恢复和异常规则。

**本节全部为我们的提案。**来源只支持左列的玩法依据，不证明参考作品已有右列的平台能力，也不意味着这些候选已纳入 PRD。候选不预设后台字段、存档格式或实现方案。

| 平台环节 | 已有玩法依据 | 我们的平台候选要求 | 后续需要核实或决定 |
| --- | --- | --- | --- |
| 启动与首次进入 | S2 用模拟手机承载探索，S4 用资料库承载检索；交互动词不同 | 作品详情说明玩家主要做什么，并清楚区分“开始试玩”“开始完整游戏”“继续游戏”；入口依据作品实际状态呈现 | G-A／G-B 的实际交互说明、可用版本、启动条件与设备支持；本轮不宣称已有可启动完整作品 |
| 试玩内容 | S1 有信息判断，S2 有通信与解谜，S4 有主动检索 | 试玩范围说明应让玩家知道能体验哪些主要交互；“试玩是否足以体验一次核心交互循环”作为未来内容评估问题 | 由未来游戏设计决定可试玩内容、停止位置与是否保存；本轮不定章节、时长、线索数量或剧情 |
| 试玩与付费边界 | S1 的信息选择有后果，S4 的探索非线性；均不能直接推出试玩切分方法 | 进入试玩前说明其范围与限制；到达边界时给出明确状态和下一步入口。区分内容到界、未取得完整访问资格与技术异常，避免都表现为空白或无响应 | 完整内容访问条件、可购状态及试玩到界的处理；具体购买流程由主代理在平台产品工作中处理 |
| 付费后返回 | 上述循环包含玩家已做出的选择或已发现的信息；是否保存没有被来源证实 | 如未来提供完整内容访问入口，应明确购买后从哪里进入、试玩记录能否继承。不能继承时，在玩家形成继承预期前说明 | 继承／重新开始规则、访问资格恢复后去向；这不是参考作品已有“无缝继承”的证据 |
| 存档与中断 | S1 依赖信息选择，S2 依赖探索与拼合，S4 依赖资料检索 | 平台“继续”入口应对应作品实际可恢复状态；在不能确认已保存时，不显示成功承诺。提供保存失败或无可恢复记录时的清楚反馈 | 各游戏实际保留哪些进展、何时保存、是否支持跨设备、更新后记录是否仍适用；均待接入验证 |
| 回访与重开 | S2 描述多结局，S3／S4 描述非线性调查；不证明参考作品的回访实现 | 回访时可辨认“继续已有记录”和“重新开始”；如重开会覆盖记录，应在操作前说明。返回平台后仍能找到同一作品入口 | 哪些回访／重开能力真实存在；是否提供多记录、分支回看或进度百分比不在本轮承诺 |

对应的一手依据：[S1](https://www.osmoticstudios.com/orwell-keeping-an-eye-on-you/)、[S2](https://store.steampowered.com/app/712730/SIMULACRA/)、[S3](https://www.herstorygame.com/)、[S4](https://store.steampowered.com/app/368370/Her_Story/?l=english)。均访问于 2026-10-24。

以上只描述平台与作品交接时应向玩家表达的状态和结果。具体的来电内容、线索检索、虚构网页、选择后果与谜题机制，留到平台完成后的两款原创游戏设计阶段。

## 5. 证据缺口与交接结论

这四个页面足以支持三种可借鉴的交互模式：资料检索与拼合、信息选择与后果、模拟通信界面的探索与解谜。[S1](https://www.osmoticstudios.com/orwell-keeping-an-eye-on-you/)、[S2](https://store.steampowered.com/app/712730/SIMULACRA/)、[S3](https://www.herstorygame.com/)、[S4](https://store.steampowered.com/app/368370/Her_Story/?l=english)

在本轮采用的玩法描述中，**没有核实**试玩与正式版如何衔接、在哪里设置付费边界、存档如何工作、退出后恢复到哪里、跨设备如何续玩。因此，不能把第 4 节写成“竞品已验证的标准方案”，也不能把页面未说明解释为作品不具备相关能力。上述事项应由主代理在平台需求评审与未来原创游戏接入时分别确认。

交接建议：阶段一优先澄清“作品入口与状态、试玩范围、完整内容访问边界、可恢复记录、返回与重开”这五类平台问题。两款完整原创游戏仍是平台完成后的独立工作；本研究不提前交付其设计，也不接管治理、PRD 或表单修改。
