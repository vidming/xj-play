# 阶段3架构复核与阶段4移交条件

状态：AC1已确认有边界的阶段3设计验收；当前允许编制阶段4实施计划，运行验证未获新增许可。更新：2026-10-28（Asia/Shanghai）。

本文回答一个问题：**当前的阶段3产出，按专业架构交付物的标准看，缺什么、补了什么、哪些只能留到实施阶段验证。** 结论是“设计可验收、运行未验证”，不是生产就绪；任何开发、建表、采购、支付接通或部署仍需单独授权。

## 2. 质量属性与容量假设（未验证）

用于阶段4压测与容量核对的起点，不是承诺值：

| 项 | 假设 | 验证方式 |
| --- | --- | --- |
| 并发会话 | 首期 ≤ 200 个在线会话 | 压测与连接池测量 |
| API 请求 | 峰值 ≤ 20 rps，突发 ≤ 60 rps | 压测；观察 P95 |
| 接口延迟 | 普通读写 P95 ≤ 300 ms；资源读取 P95 ≤ 800 ms | 压测与真实对象存储 |
| 首屏 | 静态商店首页 P95 ≤ 2.5 s（公网 4G） | 真实宿主与 CDN 测量 |
| 可用性 | 首期单实例目标 99.5%／月 | 监控与故障记录 |
| 数据量 | ≤ 50 款游戏、≤ 10 万玩家、≤ 500 万观察事件／月 | 容量估算与索引测量 |
| 恢复 | RPO 15 分钟、RTO 4 小时（CR1 研究目标） | 恢复演练实测 |
| 保留 | 普通行为明细 30 日；交易与权益记录 3 年 | 清理任务与备份保留核对 |

超过假设时必须先修订本表并重新核对容量与恢复，不得直接按原目标上线。

| 游戏运行隔离 | 独立来源、CSP、frame 导航、握手失效、匿名与登录 | 隔离矩阵全部通过 | 隔离测试记录 |
| 游客购买返回 | 有效guest Cookie同浏览器登录、注册后登录、意图交接/绑定、邮箱验证、报价、付费、权益和新run分段验证；另测登录响应丢失、交接/位置到期与两会话争抢 | 同账号同目标会话同键重试稳定；跨浏览器/换号/失效不冒领；过期位置不造成二次付款，位置不授予权益，按已确认版本规则处理 | 接口与并发用例、失败回退记录 |

## 5. 安全威胁与对策摘要

| 威胁 | 现有对策 | 残余风险 |
| --- | --- | --- |
| 伪造游戏或回跳来源 | 服务端会话 + run 归属 + 支付验签；iframe 来源与 MessagePort 校验 | 隔离与握手失效未实测 |
| 冒领游客意图 | GI-A登录时核原guest Cookie和创建时run归属；按意图的短时同库交接仅供目标会话原子消费；公开intentId不授予权限 | 登录/绑定并发、Cookie轮换、注销/撤销及跨浏览器拒绝未运行 |
| 篡改价格或权益 | 服务端报价快照与权益来源；前端价格无效 | 优惠与升级规则需用例覆盖 |
| 否认已付款 | 渠道验签、主动查单、对账与现金事实表 | 真实渠道行为未验证 |
| 越权读取存档或资源 | 每次请求重核权益、私有桶、精确版本 | 资源越权与缓存未实测 |
| 资源耗尽 | 包长与上传额度、限流、租约 | 未压测 |
| 后台权限提升 | 独立管理员认证与 RBAC、审计事件 | 未做权限矩阵回归 |
