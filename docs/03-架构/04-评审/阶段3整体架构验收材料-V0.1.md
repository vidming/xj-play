### 4.2 游客购买意图的登录交接（GI-A已选）

2026-10-28 收到实际 GI-A 消息，确认首期同浏览器服务端短时一次性交接，只允许在阶段3补设计。原缺口是 `bind` 只有当前登录 Cookie 和公开 `intentId`，无法证明原游客归属；现按[接入链路6.1.1](../03-文档/游戏接入与可信业务链路候选-V0.1.md#611-游客意图的同浏览器登录交接gi-a已确认方向)设计：登录请求同时携有效游客 Cookie 与待交接意图，登录事务固定原游客会话、原 run、意图和新登录会话/账号的关系；`bind` 只在目标会话内消费服务端交接记录。注册 ACK 不直接认领；绑定可早于邮箱验证，报价及购买仍须验证邮箱。跨浏览器不认领未绑定匿名意图；已绑定账号的订单按 PT1 重新登录核验。

GP1已确认游客在匿名意图创建后 30 分钟内、原游客会话仍有效时开始登录交接；已建立的交接另保留 15 分钟，不被原 30 分钟登录资格截断，绑定后位置最多 24 小时。这些数字由2026-10-28实际GP1消息确认，按服务端时间计算，尚未运行验证。报价有效期 10 分钟单独计算。意图只提出原 run 与 `contentKeys`，商品修订由后续报价固定；已登录玩家可直接创建账号绑定意图，不能因补游客路径而失去购买能力。过期位置不能造成二次收费，真实付款与权益独立按账号/订单核实。

Login/Intent/Bind/Run 的字段与交接数据列静态对应已复核；PLAYER 直达意图在有效同主体 run 上核版本、作品、内容和当前权限并直接 BOUND，位置从 `bound_at` 起最多保留24小时。报价携意图时仍须核当前目标会话、账号和商品覆盖；报价10分钟独立计时。登录成功但无有效交接、首次交付的 `BOUND→RETURNED`、同键重放和报价三重 revision 的守卫已进入机读契约；对应运行中的响应丢失、原游客会话撤销后的绑定、同意图两会话/换号争抢、邮箱验证、失效/取消、支付跨浏览器、游戏版本改变、先失效后回退均待验证。静态契约通过仅证明结构和设计场景，未运行服务和真实独立游戏。AC1已完成有边界设计验收；运行验证仍须后续授权。

| 验收场景（待运行） | 必须观察到的服务端结果 |
| --- | --- |
| 有效游客run登记意图，在原浏览器登录 | 仅指定意图生成目标会话交接；游客会话撤销，其他意图不被一并认领 |
| 注册后在原会话仍有效时登录，邮箱尚未验证 | 可绑定意图；报价/订单仍被邮箱验证门禁拒绝，验证后同账号继续 |
| 登录成功响应丢失，旧游客Cookie重发同key/同请求 | 返回原新会话及交接结果，不创建第二账号会话或第二交接；同key异请求拒绝 |
| 登录前游客会话过期/撤销、换浏览器或缺原Cookie | 登录可独立成功，但不创建该意图交接；`bind`泛化拒绝 |
| 登录前游客会话轮换为另一记录，或登录后玩家会话在bind前轮换且无可信谱系 | 不能仅凭浏览器相同认领旧意图；明确安全回退至重新选择商品 |
| 登录后更换账号、登出或撤销目标会话 | 旧交接失效；新账号/会话仅持intentId不能绑定 |
| 同一意图两个会话或两次并发绑定 | 只有一个与交接一致的目标会话能将意图改为`BOUND`；重复同会话同key结果稳定 |
| 购买请求后原 run 正常退出；或作品/版本变化、意图取消或超时 | 正常退出不抹创建时合法的意图；其他失效条件按交接有效期及新run版本规则拒绝或明确位置不可用；不能因失败授予权益 |
| 交接过期但报价/订单仍可查，或付款结果晚于位置有效期 | 不通过旧意图恢复handle；原账号付款及权益事实仍可查询，不重复扣款 |
| 外部浏览器按PT1重登录原已绑定账号查询订单 | 核验账号归属及支付状态，不把匿名意图交接凭据带到外部浏览器，不凭位置放行付费内容 |
| 删除/账号限制/恢复故障与意图清理并发 | 不复活过期或撤销交接，不泄露原始handle；保留必要交易事实与审计证据 |
