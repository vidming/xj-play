# 平台接口与消息桥契约草案

V0.1；2026-10-25（Asia/Shanghai）；状态：阶段3关键接口契约草案；当前公共通则；全量OpenAPI见资料目录，接口尚未运行。

配套：[接入与信任](游戏接入与可信业务链路候选-V0.1.md)、[数据一致性](数据一致性部署与运营候选-V0.1.md)。本轮覆盖跨游戏公共边界；完整HTTP操作、字典及渠道协议分别见当前OpenAPI、物理字典和双支付规格。

## 1. HTTP 通则

建议玩家API前缀 `/app-api/xj/v1`、后台 `/admin-api/xj/v1`；后台既有接口不直接改名。宿主代调平台业务API，游戏不能直接复用后台权限或平台凭据。Cookie会话写操作必须CSRF校验，CORS只允许明确来源且不替代鉴权。消息桥调用者由当前run与宿主session绑定，不接受请求覆盖playerId。

公共响应适配现有 `code/msg/data`，补充 `requestId` 供排障；成功 `code=0`，错误使用稳定机器码，不靠中文文案判断业务。私人数据及一次性链接响应 `Cache-Control: no-store`；敏感请求体/链接不写日志。资源返回二进制与准确MIME，拒绝错误类型解释为脚本；私有网关及共享缓存不得缓存可绕过当前权限的响应。

所有时间用带时区ISO 8601传输，服务端记录可信发生/核实时刻，报表明确Asia/Shanghai。金额是CNY分整数；展示换算仅用于UI。版本revision按服务端值比较，时间戳不能替代并发revision。

分页参数 `pageNo>=1`、`pageSize=12`，默认 `publishedAt DESC,id DESC`；首期已确认产品每页12项，API不擅自扩大页面规格。超出有效页返回有效页信息与原筛选，公开检索仅返回已公开且可展示对象；不可见草稿不因参数而泄露。后台可另设受控分页，不修改玩家规格。

幂等写入带 `Idempotency-Key`，作用域为“可信主体+动作+业务对象”。相同key/同规范化payload返回同操作结果；只有明确声明异步受理及查询路径的接口才返回202，当前为存档提交，data仍是SaveOperation，按其id查原操作。付款UNKNOWN等沿用各自业务对象状态；资源读取只返回二进制或错误。同key不同payload返回409。通信重试复用原key。响应缓存清理后仍靠订单/来源/渠道号等持久唯一关系防重复，不能随临时幂等记录到期制造第二份真实付款/授予。

## 2. 接口目录（候选）

| ID / 方法与路径 | 输入/返回重点 | 权限、并发及异常 |
| --- | --- | --- |
| API-C01 `GET /games` | 筛选、关键词、稳定分页；作品与声明 | 公开；无结果真实空态，不制造评分/销量 |
| API-C02 `GET /games/{gameId}` | 详情、版本/试玩/设备/范围与售卖状态 | 草稿拒绝；停售和安全暂停区分 |
| API-R01 `POST /runs` | gameId、进入意图、可选intentId；服务端选适用版本/模式 | 游客仅试玩；正式进入查权益与生命周期；意图须绑定当前可信会话，gameId等于意图作品且目标范围按意图contentKeys重核。首次交付原子BOUND→RETURNED并固定return_run_id；RETURNED仅同键同请求按return_run_id重放原run/`RunResume`，换键/换run/同键异请求拒绝；位置不授权 |
| API-R02 `GET /runs/{runId}/context` | 最小身份、版本、能力、accessRevision | 当前主体/会话绑定；会话过期拒绝 |
| API-R03 `POST /runs/{runId}/access/check` | contentKeys；逐key结果/原因 | 服务端当前权益并集；拒绝未知key；不发权 |
| API-R04 `POST /runs/{runId}/resources/read` | manifest resourceId；二进制结果 | 当前归属/状态/版本/资源覆盖全检查；无任意URL代理 |
| API-R05 `POST /runs/{runId}/ready` | 协议就绪、版本 | 每run幂等，只记可交互声明，不写现金状态 |

| API-I01 `POST /purchase-intents` | runId、contentKeys、resumeHandle | 有效游客run登记匿名意图，经GI-A交接；已登录玩家run直接登记账号/当前会话绑定意图；服务器固定原会话、作品和版本 |
| API-I02 `POST /purchase-intents/{id}/bind` | 空请求；仅发送当前登录会话、CSRF和幂等键 | GI-A：验证登录时创建的原游客会话→该意图→目标会话交接关系，原子消费并绑定账号；intentId不单独授权 |
| API-Q01 `POST /quotes` | intentId、目标productRevision | 已验证正常账号；服务器金额/抵扣、10分钟有效期及来源revision |
| API-O01 `POST /orders` | quoteId、expectedAccessRevision、key | 报价归属当前主体；expectedAccessRevision、quote.access_revision与当前守卫revision三者相等；重核来源/在途抵扣及金额。仅dueFen>0；零补款转独立升级操作不造支付 |
| API-O02 `GET /orders/{id}` | 订单/付款/交付/售后分别返回 | 本人；未知不是失败；后台查单另有权限 |
| API-P01 `POST /orders/{id}/payment-attempts` | 渠道选择标识，平台生成尝试 | 本人且订单可付；同请求幂等；返回受控渠道动作，不放密钥 |
| API-P02 `POST /payments/notifications/{channel}` | 原始渠道通知 | 不是普通CookieAPI；独立验签/商户/订单/金额核验及持久去重；应答按渠道 |
| API-E01 `POST /claims/free` | gameId、免费规则revision | 已验证正常账号；同账号/作品重复返回同授予，不产生现金 |
| API-E02 `GET /library` | 有效授予、试玩记录和受控继续摘要分开 | 本人；不能从试玩记录推成已购。`continue`只含状态/版本/时间，不含payload、剧情或handle |
| API-S01 `GET /runs/{runId}/save` | current/previous元数据；payload由独立save/read入口受控读取 | 验证邮箱、本人/游戏、游戏声明；不兼容明确反馈 |
| API-S02 `POST /runs/{runId}/save-operations` | action、baseRevision、format、payload/来源、operationId | write/import/restore/restart；1MiB；CAS及确认；冲突双方保留 |
| API-S03 `GET /save-operations/{operationId}` | 同次操作可信结果 | 本人归属；响应中的PENDING、CONFLICT及SUCCEEDED/revision分开 |
| API-A01 `POST /runs/{runId}/events` | 最小白名单eventId/type/fields | 限流/批量额度后续核准；去重、不接收现金事实作真 |
| API-U01 `POST /support-cases` | order/grant/upgrade业务关联、分类、说明 | 本人可查对象；申请不是批准；附件首版不收 |

| API-M02 `POST /refunds/{id}/execute` | 人工已批准方案revision | 后台交易权限；额度锁/来源联动、渠道未知不重复退款 |
| API-M03 `GET /reports` | metric、游戏/币种、1–366日、asOf | 后台运营金额权限；核实/未知/跨期单列，不公开个人凭据 |

完整HTTP路径、schema、状态码与认证方案以[当前OpenAPI源](../05-资料/平台OpenAPI-V0.1.json)为准；这里的API ID可供追溯，仍为待整体验收草案，不冒称已生成客户端。

零补款升级使用`POST /upgrades`，只接`dueFen=0`的已确认报价；正补款升级仍走订单和渠道核实，正补款误走升级、零补款误走订单均拒绝。两个确认入口都必须核报价归属当前主体、`expectedAccessRevision == quote.access_revision == 当前守卫revision`，重核报价有效期、商品范围、合格来源的归属/净实付/已分配/在途抵扣与revision，并验证`0<=creditFen<=priceFen`、`dueFen=priceFen-creditFen`；任一变化均拒绝并重新报价，不接受客户端金额。`Upgrade`响应必须返回目标`productRevisionId`、`priceFen`、`currency`、`promise`、`contentKeys`、抵扣与应付，不得只给内部状态。已交付时必须关联`grantId`；零补款不得伪造`orderId`，正补款订单核实交付后才可关联。查询使用`GET /upgrades/{upgradeId}`，不新增另一套升级对象。

首期付款机器契约只接受支付宝PAGE/WAP与微信NATIVE/H5；`JSAPI`及小程序不在首期，未知method一律拒绝。PT1的微信内浏览仍只负责引导系统浏览器，不通过保留枚举暗示已开放微信内支付。

RT1与CL1已于2026-10-26由实际选择消息确认，机器契约分别补入`RunCreate.intentId`/`RunResume`及`LibraryItem.continue`，详见[接入链路6.1/6.2](游戏接入与可信业务链路候选-V0.1.md#61-购买返回契约rt1已确认)。它们只完成设计收口；未运行HTTP、SDK或存档流程前，不得把“新run恢复原位置”或“库页展示继续信息”写成已实现能力。

GI-A 已于2026-10-28选定为阶段3细化方向：`POST /sessions` 的登录请求可指定待交接 `intentId`，但只有请求同时携原有效游客 Cookie 且在登录事务内证明原 run/意图归属时才建立服务端短时交接；注册 ACK 不构成交接。密码账号认证失败才使登录失败；认证成功但guest Cookie或意图不满足交接条件时仍签发PLAYER Cookie、不建交接，200 `data.state=SUCCEEDED`，可选`data.handoffError.code=INTENT_BINDING_INVALID`只给泛化提示。`bind` 用新会话与持久交接记录核验，不需要也不接收客户端转交游客令牌。匿名意图、交接、绑定后位置各有自己的到期边界；登录后邮箱尚未验证时可绑定，付款/云档仍受邮箱验证限制。详细边界及失败回退见[接入链路6.1.1](游戏接入与可信业务链路候选-V0.1.md#611-游客意图的同浏览器登录交接gi-a已确认方向)。只读订单跨浏览器重核已绑定账号，不重新认领未绑定意图。

## 3. 错误与重试

| HTTP / 机器码 | 意义 | 客户端处理 |
| --- | --- | --- |
| 401 `AUTH_REQUIRED` | 未识别/过期 | 关闭私人上下文，受控登录后新run重核 |
| 403 `EMAIL_VERIFICATION_REQUIRED` | 已识别但验证前不能新增资产/云档 | 验证并回原意图；不清本机试玩 |
| 403 `ACCESS_DENIED` | 当前范围无权 | 可展示购买/返回；不能本地置paid |
| 404 `OBJECT_NOT_AVAILABLE` | 不存在或无权得知对象 | 不泄露其他账号/作品信息；内部日志区分原因 |
| 409 `QUOTE_CHANGED` / `SOURCE_PENDING` | 价格/来源变化或结果未明 | 展示重核，不自动接受新价格/二次扣款 |
| 409 `SAVE_CONFLICT` | baseRevision不再当前 | 展示双方来源、重新选择；第三来源留本机 |
| 409 `IDEMPOTENCY_MISMATCH` | 同key不同请求 | 纠正调用；不自动换key绕过 |
| 409 `INTENT_BINDING_INVALID` | 意图不存在、不属于当前会话/账号/作品、交接缺失或过期、已消费/取消；对外泛化 | 不恢复位置；继续可用试玩，必要时登录后重新选商品；不能据此认定付款失败 |
| 413 `SAVE_TOO_LARGE` | 编码后未压缩payload超过1048576字节 | 拒本次，原档及恢复点不轮转 |
| 422 `PROTOCOL_UNSUPPORTED` / `SAVE_INCOMPATIBLE` | 协议或格式不兼容 | 返回适用版本/迁移/支持，不能假报恢复 |
| 423 `ACCOUNT_ACTION_RESTRICTED` | 注销申请等生命周期限制 | 保留查单/售后/撤回，禁止新增资产/云档写入 |
| 429 `RATE_LIMITED` | 明确限流 | Retry-After提示；邮件另遵守已确认60秒/每小时5次 |
| 503 `GAME_SUSPENDED` / `DEPENDENCY_UNAVAILABLE` | 游戏暂停或依赖不可核实 | 说明范围、重试/返回/支持；不授予临时付费权限 |
| 202 / `data: SaveOperation` | 存档提交已受理但未完成，不是错误码 | 按data.id查原操作；不能当作保存成功 |

只对明确可重试且同一业务key的网络/临时故障做有界退避；幂等层未知先查询。渠道通知异常与业务拒绝不套普通JSON应答，避免渠道误认已处理；具体应答留渠道核查。

## 4. 消息桥信封与兼容

```json
{
  "protocolVersion": "1.0",
  "channelId": "本次握手随机值",
  "requestId": "游戏生成的本次RPC标识",
  "method": "access.check",
  "params": {"contentKeys": ["story.main"]}
}
```

RPC响应包含对应requestId、`ok/result`或稳定`error.code`；schema拒绝不允许字段，限制尺寸、并发和白名单动作。RPC requestId只关联通信，持久化写入另用operationId/Idempotency-Key；改变requestId不能绕过业务幂等。

资源二进制通过当前MessagePort传递；游戏只见自己已获准的字节，不见平台会话。消息的用户字段全部无效；服务端从run/会话确定归属。重大协议变更发新major并保留旧版兼容窗口；具体支持窗口随版本治理核准，不能凭空写“永久兼容”。

## 5. 已确认的非现金售后关联

既有RF1允许零补款升级/免费授予的非现金售后，但固定PRD `support_request_success` 列有必填 `order_ref`。有些有效售后没有付费订单，不能为了凑字段制造假付款。

当前有效决策已经确认：正式售后及事件契约采用 `businessRef = {type: order|grant|upgrade, id}`；确有订单时附 `order_ref`，没有订单则明确非适用，不用随机占位订单。现行OpenAPI、事件Schema及契约阅读说明已承接此规则，售后资格与现金规则不变，不再作为待选字段提交。固定PRD与细化规则结合阅读，以[当前有效决策](../01-决策/当前有效决策.md)记录的实际确认为准，文档同步不重新授予实施权限。

## 6. 注销与晚到账的交叉约束

注销申请期间的冻结不能使可信晚到账丢失；记录实际现金及原订单，关联人工在途核对，不自动向已停止访问主体开启正式运行。最终处理后出现晚到账仍保留最小查证凭据，走受控支持/履约或退款方案，不恢复旧会话、不将同邮箱新账号当旧资产承接人。具体人工选择与现金执行逐案留痕，不能由补偿任务擅自承诺退款完成。
