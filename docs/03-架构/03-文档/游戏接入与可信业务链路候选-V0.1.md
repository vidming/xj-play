# 游戏接入与可信业务链路候选

版本：V0.1；更新2026-10-26（Asia/Shanghai）；阶段3架构细化；状态：设计草案，未实现、未整体验收。

方向：[当前有效决策](../01-决策/当前有效决策.md)。产品依据：[固定PRD](../../02-产品与设计/01-产品规划/01-文档/间隙PLAY-产品需求文档-V1.0-提交稿.md)、[账号与存档规则](../../02-产品与设计/01-产品规划/01-文档/账号进度与退款规则-V1.0-提交稿.md)、[CAP](../../02-产品与设计/01-产品规划/01-文档/游戏与平台公共对接能力需求-V0.1.md)。规范依据：[本轮核查](../05-资料/接入与渲染规范复核-20261025.md)。

## 1. 独立前端可以实现什么

G-A 的预写故事、选择、关系与多结局，G-B 的线索、链接、虚构网页、推理及结局，都可以由独立前端工程承载。这里说的是本项目的可行设计，不推断参考作品的内部实现。游戏可用原生 HTML/JavaScript 或自选框架。

浏览器中的玩法状态不具备交易证明效力。平台可信服务负责账号、邮箱验证、订单、付款事实、权益与受保护内容交付。若未来游戏需要实时 AI、多人同步或私密外部服务，由游戏自行声明额外后端，不把这些能力强加给所有游戏。

本轮定义协议，不写完整游戏、不把最小接入样例当完整作品。后续 G-A/G-B 仍须独立设计、完整制作、真实接入并分别验收。

SD2已明确所有平台及每个独立游戏的表/表数据先共用当前MCP数据库`xj_play`：平台`xj_`，各游戏登记`xjg_<gameKey>_`。这是存储归属，游戏仍独立开发；不要求纯前端游戏新增玩法后端。需要游戏专有持久逻辑时，由最小权限的可信游戏服务读写本游戏表，经平台接口核身份、权益及数据归属；浏览器不直连数据库。同库不使跨服务HTTP调用自动成为同一事务，删除和恢复必须覆盖所有关联游戏私人数据，详见[同库归属与恢复边界](部署资源与恢复规格.md#73-平台与每个独立游戏的同库归属)。

## 2. 三个平面与来源隔离

| 平面 | 内容与职责 | 信任及暴露 |
| --- | --- | --- |
| 商店/运行外壳 | 账号、商品确认、购买返回、加载/静音/退出；受控宿主消息桥 | 持有平台会话；只代理白名单动作，不解释剧情 |
| 独立游戏 | 自有页面、剧情、谜题、路由、局内状态；调用 SDK | 不接触平台 Cookie、邮箱、支付密钥或刷新令牌；游戏事件为不可信输入 |
| 可信业务与资源 | 订单/支付/权益、存档归属、资源授权、发布及审计 | 每次按服务端当前状态校验；不相信游戏传来的用户或解锁字段 |

部署使用概念名称 `store-origin`、`admin-origin`、`game-origin(gameId)`，均不是已购买域名。游戏之间独立来源，游戏与平台不同来源；资源方案优先评估游戏与平台分开可注册域，避免错误共享 Cookie 范围。平台会话使用宿主限定、Secure、HttpOnly Cookie，具体会话实现需适配旧认证底座。管理端身份与玩家身份分别校验，不能用管理员登录态购买玩家商品。

iframe 初始建议 `sandbox="allow-scripts allow-same-origin"`，只在**与父平台不同来源**的游戏来源使用；不授予顶层导航、弹窗、表单和下载，确有用途时单独审核。跨来源不是权限系统；平台必须另做 CSRF、对象归属、权限检查。游戏资源服务不托管平台 API，不转发平台 Cookie。CSP 的 frame-ancestors、script-src、connect-src、Permissions-Policy 按声明收紧；本轮没有进行实际隔离测试。

游戏单页内路由优先；G-B 可以实现“多站点”视觉与多路由，不需要真实访问参考站点，也不把每个虚构网站放到商店同源页面。确需整页导航的游戏，每次加载重新握手并由宿主重新绑定当前 frame；旧消息桥立即失效。外部链接由宿主展示目的地址并受控打开，不获得平台身份。

## 3. 资源包与内容范围

资源包由游戏工程构建，运营审核上传。建议 manifest：

```json
{
  "manifestVersion": "1.0",
  "gameKey": "ga",
  "gameVersion": "1.0.0",
  "platformProtocol": {"min": "1.0", "max": "1.x"},
  "entry": "index.html",
  "capabilities": ["context", "access", "resources", "purchase", "save", "events", "return"],
  "save": {"format": "ga-save/1", "accepts": ["ga-save/1"], "maxBytes": 1048576},
  "routes": {"mode": "spa", "fallback": "index.html"},
  "content": [
    {"key": "trial.intro", "availability": "trial"},
    {"key": "story.main", "availability": "entitled"}
  ],
  "resources": [
    {"path": "index.html", "visibility": "public"},
    {"path": "engine.js", "visibility": "public"},
    {"path": "content/main.bin", "visibility": "protected", "requiresAll": ["story.main"]}
  ]
}
```

示例仅说明结构，不是已制作游戏或最终 API。内容 key 由游戏定义；场景、章节和调查区域可以跨多页面。商品范围是这些 key 的集合，不以页面数、点击次数或重新进入次数收费。每个 key 的已售含义不能复用或缩减。

公开引导包只有入口、公共引擎、必要样式和合法公开的试玩内容；正文、答案、隐藏结局等付费数据按范围拆到私有对象。保护所需素材不能顺手进入 sourcemap、HTML 注释、打包常量、预加载或 Service Worker 离线缓存。付费 JS 模块若含内容也必须受控；首批自研游戏优先采用公共引擎 + 受控内容数据，避免仅对正文拆包却把答案留在公开脚本。

受控资源引用必须在发布 manifest 中列出；发布后由平台为索引项分配 resourceId，Run.resourceIndex 向游戏提供固定版本的 path→resourceId 映射，SDK精确匹配后仅用该编号读取。索引不是权益或秘密；路径不得包含答案或隐藏剧情。默认一个资源要求 `requiresAll` 中全部 key，公共共享素材另行明确标为公开。服务端只解析已发布对象索引，不接受任意 URL、桶名或文件系统路径。路径标准化拒绝 `..`、绝对路径、编码绕过、大小写碰撞及符号链接；上传包检查解压后大小、文件数、压缩比、恶意脚本/外联、来源许可。具体资源额度留完整规格节点核准，不虚构已做扫描。

版本不可原地替换：包摘要、manifest 摘要、资源清单、协议/存档能力和审核结果与版本绑定。旧资源在仍需履约时保留，不能因商店停售删除已购可用版本。资源回滚不自动回滚玩家存档或历史商品承诺。

## 4. 运行握手与服务端上下文

1. 外壳向平台请求创建 run。服务端由会话获得玩家或匿名试玩主体，校验游戏/版本状态与进入模式；忽略请求中的账号/购买状态。
2. 返回 `runId`、固定版本、游戏来源、协议范围、模式、允许能力及引导路径；不把平台长期令牌放进 iframe URL、referrer 或本机存储。
3. 游戏加载完成发送 `HELLO`。宿主验证 `event.origin`、当前 `iframe.contentWindow`、预期 run/版本和协议；宿主用准确 `targetOrigin` 建立 MessageChannel，发送本次频道随机值与最小上下文。
4. 之后只在该 MessagePort 接收白名单 RPC，校验 `protocolVersion/requestId/channelId/method/params`。随机值隔离会话，**不是用户身份或交易证明**。frame 导航、账号切换、登出或新 run 都关闭旧端口。
5. 只有游戏初始化并声明可交互后调用 `runtime.ready`，平台才记录就绪。超时显示重试/返回；按钮点击、iframe load 和创建 run 都不等同就绪。
6. 每次资源、存档及访问请求，宿主调用平台 API；服务端重新检查会话主体、run 归属、生命周期、作品状态、版本与当前权益。前端拦截只是体验措施。

匿名试玩使用平台签发的匿名会话上下文，只能访问声明的试玩资源。不能用传入 guestId 枚举其他游客记录；游客没有账号私人云档。本机进度由游戏按作品及格式保存，敏感账号云档默认不在公共缓存持久化。登录后新 run 与经核验账号绑定，旧匿名 run 不原地变成正式 run。

会话失效返回 `AUTH_REQUIRED`，让游戏保存其支持的本机未上传状态，清除私人展示并回到外壳；不能偷偷降级为另一账号继续写同一云档。注销申请状态冻结云档写入、新购/领取及新开正式运行，最后确认处理后撤所有适用运行上下文；保留受控查单/支持出口。

## 5. SDK / 消息桥接口草案

SDK 是可选的薄封装，允许游戏按协议自行适配，不提供统一剧情引擎。

| 方法 | 输入 | 输出/效果 | 关键限制 |
| --- | --- | --- | --- |
| `context.get` | 无 | game/version/run、模式、能力、作品内匿名主体标识 | 不返回邮箱或平台长期令牌；游戏不能指定用户 |
| `access.check` | `contentKeys[]` | 每个 key 的允许/拒绝及原因、accessRevision | 查询不授予权益；资源读取仍重核 |
| `resources.read` | manifest 中的 `resourceId` | MIME、摘要、字节流 | 宿主经可信网关取回并传递二进制；不返回永久公网地址 |
| `purchase.request` | 所需内容 key、游戏自有 resumeHandle | 购买意图编号，打开平台确认路径 | 不接受金额/账号/已付字段；不自动下单扣款 |
| `purchase.status` | 本 run 的 intentId | 未付/待核实/有效访问等分开结果 | 取消/回跳不能自行标成功；返回后重查权益 |
| `save.describe/read` | 无或恢复来源标识 | 当前/上一恢复点及格式、revision | 已验证邮箱和本人归属；游戏解释 payload |
| `save.write/import/restore/restart` | payload、格式、baseRevision、operationId | 已确认保存/冲突/未知及修订 | CAS；恢复/导入/重开有明确确认；不据 payload 授权 |
| `save.operation` | operationId | 同次操作的可信结果 | 超时先查同次操作，不新建覆盖 |
| `events.report` | eventId、白名单事件/最小字段 | 接受/重复/拒绝 | 不接受 `payment_succeeded` 等现金事实为真 |
| `runtime.ready/exit` | ready 或退出原因 | 运行结果/返回意图 | 错误通过已定义事件报告，不新增未定义RPC；退出不等同保存成功 |
| `platform.return` | 宿主登记的返回意图 | 返回平台允许位置 | 不接受任意跨站 return URL |

资源传输采用先元数据、后 ArrayBuffer 分块与逐块确认；完整长度和摘要核验后才向游戏交付。传输控制帧、取消、零字节资源及全局内存预算详见[SDK与适配器方案](游戏SDK与适配器方案.md)。浏览器端解析、媒体 Blob 和相对路径由游戏适配器处理；这意味着不是“任意现有网页零改动即可安全收费”。首批完整游戏需按上述分包与桥接口实际适配。外部托管游戏 I2 预留授权码/PKCE、可信后端及资源受控交付契约，本轮不实现第二套运行方案。

协议采用独立版本；major 不兼容则拒绝启动并给支持出口。当前契约只支持1.0，未来minor须发布对应Schema及兼容表后才可协商；capabilities不自动接受未知版本或方法。SDK 升级不强制改游戏玩法。当前会话/权限变更使用宿主通知提示游戏，但最终访问仍由服务端检查。断网不授予新权限、不虚构保存或付款成功。

## 6. 购买返回与三类计费

购买意图由平台保存 `intentId/gameId/runId/contentKeys/productRevision/resumeHandle/subjectBinding`；resumeHandle 是游戏自有不透明游玩位置，不能含平台凭据，不作为授权依据。平台只允许返回登记的作品入口，游戏在新上下文就绪后恢复 handle，并再次确认当前访问。

游客点击购买 → 平台登记意图 → 登录/注册/验证邮箱 → 明示当前账号和原商品 → 可选 GP1 进度导入 → 可信报价 → 玩家确认 → 订单/渠道付款 → 核实付款 → 交付权益 → 新 run 恢复原游戏。取消任一步都能返回仍可试玩范围；跳过导入不阻断购买。

| 模式 | 游戏侧映射示例（非游戏定稿） | 平台可信行为 |
| --- | --- | --- |
| 买断 | G-A `story.main/ending.pack` 或 G-B 一组调查区域 | 商品快照明确覆盖 key；买断不默认为所有未来内容；重复进入不消耗 |
| 章节 | G-A 自有章节、G-B 一组相关调查档案 | 每章可跨页面；服务端核实覆盖并拒绝重复购买已完全覆盖范围 |
| 场景 | 游戏自有一段剧情或调查场景 | 不根据 URL/路由/点击推导计费；场景访问权可重玩，不增加次数扣减 |
| 章节/场景升级买断 | 合格历史现金来源与目标覆盖范围 | 按 UP1 净实付只抵一次；报价10分钟且提交重核；零补款记升级、不造付款 |

免费完整领取需账号与邮箱验证，产生独立免费授予来源；不是零元渠道付款。部分重复覆盖、进行中的升级/退款及失效报价返回明确原因；不通过修改存档或浏览器标志规避。

### 6.1 购买返回契约（RT1已确认）

2026-10-26实际选择消息确认RT1。当前机器契约已增加可选`RunCreate.intentId`、受控`RunResume`以及`Run.resume`；这只完成设计收口，不代表OpenAPI已运行或“付款后恢复”已通过验收。

购买返回必须同时满足以下约束：

- 新 run 只由当前可信会话创建；服务端从会话和原意图确认主体、游戏、原内容范围及当前访问，不接受客户端覆盖账号或权益。
- `resumeHandle` 只表示游戏自有的不透明位置，不含平台令牌、邮箱、支付信息或授权结论；长度有界且不得写入 URL、日志或公开缓存。
- 只有意图与当前主体、作品匹配，且新 run 的目标范围已通过当前权益或试玩规则核验后，才可向该 run 交付位置；返回位置失败不得阻止仍获准的访问，也不得自动解锁。
- 返回位置不得跨游戏或跨不兼容版本静默复用；服务端以`RunResume.reason`明确表达不可用原因，权益校验仍独立执行。
- `GET /purchase-intents/{intentId}` 只返回绑定、状态与是否具备受控返回条件，不向任意调用者回显原始位置。

机器语义：

1. `RunCreate.intentId`可选，只接受公开意图UUID；服务端按当前会话和匿名绑定核验，意图不存在、不属于当前可信绑定或作品不一致时返回`INTENT_BINDING_INVALID`，不泄露对象详情。
2. 服务端重核后先固定本次run的游戏版本。`RunResume.versionId`必须等于`Run.versionId`；跨版本不静默复用位置。
3. `RunResume.state=AVAILABLE`时必须返回`handle/versionId/expiresAt`，不得同时返回不可用原因；位置只通过受控宿主通道交付，不回显在URL，不作为权益。
4. `RunResume.state=UNAVAILABLE`时必须返回明确原因，且不返回handle、版本或到期时间。位置不可用不降低已获准的内容访问，也不自动授予付费范围。
5. 意图消费、run绑定和位置交付必须有界、幂等并绑定当前会话。重复创建需返回同一有效结果或明确不可用，不能跨浏览器无限复用。
6. `GET /purchase-intents/{intentId}`只返回`returnAvailable`等摘要，不回显原始handle。

保留RT2／RT3为未选项，不再实施；选择RT1不等于授权修改源码、生成SDK实现或补齐跨浏览器运行测试。

### 6.2 “我的游戏 / 继续游玩”契约（CL1已确认）

2026-10-26实际选择消息确认CL1。`LibraryItem`已增加受控`continue`摘要；我的游戏页面仍不得据试玩记录推断已购买，也不得展示剧情原文、线索内容、存档payload或原始`resumeHandle`。

`ContinueSummary`语义：

- `available`、`saveState`、`accessState`必填；`versionId/lastActivityAt`仅在可继续时提供。
- `available=true`时`saveState`必须为`AVAILABLE`、`accessState`必须为`ALLOWED`，并给出适用版本与最近活动时间。
- `saveState=CONFLICT`或`INCOMPATIBLE`时`available`必须为false，库页展示真实原因；进入游戏后仍走存档接口核验，不能由库页替代读档成功。
- `accessState=DENIED/PENDING`时不得标记可继续；试玩记录不转换为已购。
- 摘要不得包含payload、剧情文本、资源路径、原始handle或可用于绕过授权的内容标识。
- 只对当前主体、当前账号生命周期和可见作品派生；注销、暂停、退款和冲突期间按当前可信状态过滤。

保留CL2／CL3为未选项，不再实施。CL1只确认库页摘要方向，不授权生成实现、建表或把摘要当作权益/读档证明。

## 7. 存档、退款与故障

SS1：每账号/游戏一个当前档 + 一个上一恢复点；1 MiB 按编码后未压缩数据计量。采用不透明二进制 payload + 元数据，不限定 JSON 剧情树；存档不允许夹带受保护资源作为再分发方式。版本兼容由游戏声明并完成实际读档确认。

写入带 baseRevision；成功替换时旧当前成为上一恢复点。冲突先保留已接收的双方来源并冻结普通替换，解决前第三份新来源留在来源端、明确未云保存。导入/恢复/重开都通过独立 operationId 和同一并发守卫；导入可跳过；超时先查已提交 operation。冲突选择后目标再次变化则重选，不比较设备时间自动覆盖。

游戏的confirmed字段不是玩家确认凭据；宿主必须先显示并取得绑定当前账号、run、动作、revision及来源的明确同意，再提交覆盖。期间切账号或目标变化须重新确认；服务端继续核归属、CAS和幂等。普通自动保存不增加逐次弹窗。

退款核实后撤对应来源并更新 accessRevision；其他有效来源并集保留。已经读到浏览器的内容无法绝对收回，当前及后续服务端受控读取重新核验。进度保留但不能代替已失效权限，禁止退款时直接删除整份故事/线索档。

| 故障 | 平台/游戏反馈与恢复 | 不能误判 |
| --- | --- | --- |
| frame 导航/桥失联 | 关闭旧桥、重新握手；保留可用本机状态 | 不能自动将上一个 frame 的 RPC 当当前请求 |
| 资源拒绝/作品暂停 | 返回访问/暂停原因、购买或支持出口 | 不能 fallback 到公开付费文件 |
| 付款超时/通知乱序 | 待核实、按原订单查证 | 不标失败、不再次下单制造重复付款 |
| 已付款交付失败 | 显示已收款/交付处理中，重试交付任务 | 不要求再次购买 |
| 游戏崩溃 | 独立运行故障，重进不扣次数 | 不倒改真实付款或保存成功 |
| 云档响应丢失 | 查同 operationId | 不凭超时重复覆盖 |
| 切账号/会话撤销 | 关闭 run、清私人展示、按新账号重核 | 不自动继承旧账号权益/云档 |

## 8. 生命周期与验收边界

包上传隔离区 → manifest/资源/许可静态检查 → 受控预览 → 协议/隔离/存档兼容验证 → 有权运营审核 → 发布不可变版本及商品范围 → 运行监测 → 必要回退/普通停售/安全暂停。预览令牌短期、限作品版本和操作者，不把隐藏链接当权限。正式与预览标识贯穿订单、运行、事件及存储。

每版映射兼容范围、资源摘要和已售承诺；发布/回退需要并发 revision。安全暂停阻断受影响新启动和资源读取，说明状态及支持；普通停售停新售，仍允许有效已购访问；永久停止按已定 POL-12 单独核对履约/退款，不删除现金事实。

后续必须实际覆盖 INT-01–16，以及串账号/串游戏、伪造 paid、猜资源路径、回退读新档、退款后读取、桥重放、第三份冲突、注销恢复不复活。当前仅有设计与图表自动检查，以上业务和隔离验收全部未执行。
