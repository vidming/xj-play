## 2. 跨模块不变量

1. 浏览器、游戏消息和支付回跳都不提供可信身份或购买证明；服务端用当前会话、run、订单核实结果和权益来源判定访问。支付到账与权益授予分开记录，重复通知和未知结果须可查证。
2. 平台 `xj_`、底座及各游戏表虽同库，但前缀只是命名登记。运行、迁移、备份与游戏可信后端按明确表清单配置最小权限；应用层守卫归属与删除一致性，迁移不得产生外键。
3. 匿名试玩只能读声明的试玩范围；登录后创建新 run。买断、章节、场景按游戏自有 `contentKey` 映射，同一有效授予不因返回或重进重复收费。
4. 存档 payload 由游戏解释，平台只负责归属、revision/CAS、恢复点与操作幂等；事件上报是低信任输入，不直接改变现金或权益。[迟到事件的判定顺序与参数记录](数据一致性部署与运营候选-V0.1.md#62-迟到观察事件的受理边界参数已确认)由EP1确认窗口72小时、时钟容差5分钟；ER-A 已确认首期仅在 GAME run 运行中及 WEB 当前浏览会话有效时重试观察事件，结束后旧队列不接收、计入分析覆盖缺口。[结束后补报凭据](数据一致性部署与运营候选-V0.1.md#63-正常结束-run-的补报归属证明未来扩展候选不属首期)仅属未来候选，未进入 OpenAPI；已撤销或已删除的 run 不因窗口恢复资格。
5. 已发送给浏览器的内容无法事后收回；受控读取每次重查权限。暂停、退款、账号删除与恢复的禁用条件不得只靠客户端或同库旧快照判断。

## 3. 阶段门禁与剩余工作

**当前可审的是架构方案及静态契约，不是最终生产制品或真实业务闭环。**完整系统总图、游戏接入图、关键时序、ER、OpenAPI/桥 Schema 和部署恢复规格应一起审阅；图中存在尚未落地的组件，其连线表示设计中的调用或数据职责，不证明服务已经存在。

2026-10-28实际AC1接受当前有边界设计验收。三图、当前49表ER的9分区／图例／结构总览、551列模型文字与边界已复核；未声称逐条连线全路径人工验收。GP1确认30／15分钟及24小时，EP1确认72小时／5分钟。ER-A排除首期结束后补报，未来扩展凭据仍须另审。

允许开始编制阶段4计划，将实连、真实支付、游戏隔离、对象存储、备份恢复与管理端11处类型错误纳入任务及证据门槛。阶段4当前不执行这些运行工作，不授权开发、建表、采购、支付接通或部署。详见[架构移交清单](../04-评审/阶段3架构复核与阶段4移交条件-V0.1.md)。

## 4. 后续终端与发行渠道的扩展边界

| 方向 | 当前可复用的边界 | 尚待产品定义与技术核查 |
| --- | --- | --- |
| 移动端 | 首期响应式网页仍使用平台 API、商品/权益和游戏协议。后续若做独立客户端，身份交换、运行容器、下载与资源读取要由该终端单独适配；游戏自有玩法数据仍按其作品/版本归属。 | “移动端”是商店客户端、游戏运行容器还是发行渠道；终端支付、离线策略、应用审核与资源分发成本。未在首期开发原生 App。 |
| 小程序 | 平台侧商品、权益来源与 contentKey 概念可保持，终端会话、游戏运行和资源读取不能仅因为网页协议存在就视为兼容。 | 是平台商店入口、完整游戏容器还是渠道；身份、内容、支付和包体能力需要按目标平台届时规则逐项核查。首期不实现。 |
| Steam | 若作为独立游戏发行渠道，应由游戏自身的发行包和平台侧商品/权益映射策略决定是否互通；不能把 Steam 账号或外部购买回执直接信为本平台权益。 | 是商店客户端、游戏发行渠道还是运行容器，以及跨渠道购买/存档是否互通，均未确认。未确定前不引入 Steam SDK 或交易依赖。 |

游戏接入协议独立于具体前端框架与渠道；兼容版本、服务端身份核验、权益来源和游戏自有 `contentKey` 映射是扩展时须保留的条件。以上为扩展设计边界，不表示未来终端的范围、成本或选型已批准。
