### 4.1 CF1 的框架事实与实现待验项

Context7 返回的官方文档支持：`nuxt generate` 或 `nuxt build --prerender` 生成可托管的 `.output/public`；该静态产物不包含可运行的服务端 endpoints。预渲染会输出 HTML 与 payload，并可生成 `200.html` / `404.html` 回退；`routeRules` 的 `prerender: false`、`prerender:generate` 中的 `route.skip` 可用于控制生成范围。[N6][N7]

这些是框架能力，不是隐私保障或主机路由验收。后续需验证：

1. 只让公开快照进入构建，扫描 HTML、payload 与 source map，确认不带私人资料、订单、受控正文或生产凭据。
2. 私人路由客户端请求 Java API；禁止把受保护内容放进 Nuxt 静态 payload；API 鉴权不依赖“没有预渲染”。
3. 只对已声明的私人客户端路由配置回退；公开不存在页面保留真实 404，未知 API 不回商店 HTML。
4. 静态宿主能否支持同源 API 反代、Cookie、发布原子切换与回退；本轮未选定供应商。
5. 公共渲染滞后时停售和交易权限由 Java 即时拦截；不等待重建才拒绝交易。

以上继续沿用既有设计边界；实际 Nuxt 4.6.2 配置、API 调用和宿主行为待后续授权验证。

复现源只保留[静态机制夹具](../评审/静态机制夹具/package.json)、其锁和最小页面；不保存node_modules、生成站点或下载副本。后续可在新的隔离目录复制该夹具，以精确Node/pnpm执行`install --frozen-lockfile --ignore-scripts`及`node node_modules/nuxt/bin/nuxt.mjs generate`，再运行[静态校验工具](../评审/校验Nuxt静态机制.cjs)。精确工具重建入口为[隔离工具获取](../评审/获取AV1隔离工具.py)，按当前记录的URL与摘要创建tool-paths.json；Maven沿用本机既有入口。Java和管理端复现入口分别为[Java验证工具](../评审/执行隔离Java兼容验证.py)、[管理端预检工具](../评审/执行管理端隔离预检.py)；工具参数指向独立临时目录，禁止指向原工程。调用顺序为工具获取脚本＋工作目录、Java脚本＋同工作目录、管理端脚本＋同工作目录；管理端默认从当前记录读取公开预检输入，不依赖将被清理的临时JSON。重建工具获取入口仅完成语法/输入核查，不为验证归档重复下载制品。各子检查失败保留真实退出码，Python总退出码不把失败包装为成功。

本轮夹具曾因漏带Lombok编译约定、过宽排除业务config目录而产生假失败，已修正并清理相关副本产物后重测；首轮缺文件诊断不列作原工程缺陷。最终结果以上表和当前记录为准。待办仍是管理端类型与许可/模块边界、限制尾部恢复证据路线、SeaweedFS精确制品/恢复组合及实际商户/资源条件；没有把它们改写成通过。
