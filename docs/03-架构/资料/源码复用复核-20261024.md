## 3. 管理员认证、权限与多租户

### 3.1 管理员认证链

**[事实]** 当前登录属于管理后台：`AuthController` 路由 `/system/auth`，含账号密码、登出、刷新、权限信息、注册、短信和社交登录；`AdminAuthServiceImpl.getUserType()` 返回 ADMIN，用户实体是继承 TenantBaseDO 的 AdminUserDO，含部门和岗位。账号密码检查、验证码及统一登录成功前的用户禁用检查均有源码。密码编码 Bean 使用 BCrypt。**[建议]** 可作为管理端认证候选，不把管理员注册接口直接用作玩家注册。证据：S15、S16、S17、S21、S73。

**[事实]** 管理员注册另受 `USER_REGISTER_ENABLED_KEY` 对应配置值与租户账户配额限制；源码有入口不意味着匿名注册当前开启。**[未验证]** 实际开关、验证码开关、短信和社交服务可用性没有读取或验证。证据：S16、S73。

**[事实]** Token 是 UUID 形式的不透明字符串，而非从源码注释推断出的 JWT：token service 持久化访问/刷新令牌，优先 Redis、再经 mapper 取访问令牌；提供过期检查、刷新时清理旧访问令牌、登出删除关联刷新令牌。token filter 检查 API 推导的用户类型与 token 用户类型一致。默认 API 前缀类声明 `/admin-api` 与 `/app-api`。证据：S18、S19、S14。

**[事实]** `getAccessToken` 具有兼容分支：访问令牌未查到时，会用传入字符串查刷新令牌，并把未过期的刷新令牌转换为访问身份。**[建议]** 若将 token 框架用于新玩家域，应专门评估并收紧这个兼容行为，保持 access/refresh 的用途边界；不是直接复用即可满足新的会话规范。证据：S18 的 103—139、208—213 行。

**[事实]** filter 中有 mock 登录分支，由 `getMockEnable()` 控制；安全链开启方法权限、使用无 Session 的 token 认证、收集 `@PermitAll`/配置放行规则，其余请求要求认证。**[未验证]** 未读取任何 mock 开关、模拟凭据或部署放行清单，不能推断当前 mock 已开启，也不能证明生产已关闭。证据：S19、S20。

### 3.2 权限不是只有前端按钮

**[事实]** 后端权限服务通过启用角色、permission 对应菜单、角色菜单集合判断权限；未找到 permission 对应菜单时拒绝，超级管理员有特殊放行。Controller 可用 `@PreAuthorize("@ss.hasPermission(...)")`，字典、任务、文件查询/删除等均有实例。后台部门/本人数据权限的 system 注册明确列出 AdminUserDO、DeptDO；规则仅处理 ADMIN 用户。证据：S20、S21、S22、S23、S24、S33、S44、S72。

**[建议]** 复用 RBAC 与后台权限表达式、菜单结构；玩家“只能读自己的订单/权益”仍需业务所有权检查，不能依赖前端按钮、部门数据权限或普通已登录状态自动获得。新业务实体/查询不在 system 当前配置中，必须独立确定其权限与租户规则。证据基础：S23、S24、S17、S59—S61。

**[事实]** 前端入口加载守卫；用户信息从 `/system/auth/get-permission-info` 获取，缓存 menus 后生成动态路由，`hasPermi` 通过权限集合删除无权限元素。用户信息刷新失败且已有缓存时会保留缓存继续进入界面。**[建议]** 保留已验收的菜单/按钮交互，但后端必须是最终授权边界；缓存菜单可以陈旧，不能据其显示结果判定权限仍有效。证据：S50、S51、S52、S53、S54、S58。

**[事实]** token 默认通过 WebStorageCache 的 localStorage 保存，记住登录表单时密码以可还原方式处理并缓存 30 天；Axios 给请求加 Bearer，刷新接口把 refreshToken 拼到 query。**[建议]** 管理员会话适配评估应覆盖浏览器脚本读取风险、共享终端的记住密码行为、代理/访问日志中的刷新参数；本次没有读取存储内容、加密密钥或配置。证据：S55、S56、S57。

### 3.3 多租户存在，但不是玩家/订单业务模型

**[事实]** 租户自动配置类允许 `yudao.tenant.enable=false` 禁用，缺省匹配启用；它声明 SQL 租户拦截器、上下文过滤器和安全过滤器。上下文来自请求租户标识并在 finally 清理；安全过滤器比对登录用户租户与请求租户，必要时补齐，并验证租户有效。tenant service 检查租户存在、禁用、过期；套餐影响租户菜单集合。证据：S25、S26、S27、S30。

**[事实]** 数据库隔离依赖拦截器和模型元数据：TenantBaseDO 子类不忽略租户；显式 `@TenantIgnore` 可忽略；找不到 MyBatis TableInfo 的表在当前实现中被忽略。访问其他租户使用 `visit-tenant-id` 与 `system:tenant:visit` 权限，并在完成后切回。前端只在环境开关为 true 时携带 tenant-id，登录身份存在且满足条件时附加 visit-tenant-id。证据：S28、S29、S57。

**[建议]** 多租户只作为候选隔离机制保留。需先由架构决策明确租户代表平台、商户还是其他组织，避免将玩家 ID、游戏区服或权益持有人直接当租户。后续检查新表实体映射、跨租户运营权限、忽略租户的公共表和异步上下文；不得仅因有 tenant-id header 就宣称数据隔离完整。

**[未验证]** 不读取运行配置或数据库，因此不知道租户是否实际启用、哪些表/URL 被额外忽略、菜单/角色是否正确初始化、是否存在 SQL 绕过以及跨租户越权是否被运行阻断。

### 4.3 任务：具备调度管理和重试，业务可靠性仍需适配

**[事实]** JobController 有创建、更新、启停、触发、同步、分页、导出等接口并标注权限；服务校验 cron、handler 唯一性和 Spring Bean 是否实现 JobHandler，再维护任务及调度。对应前端 API 已存在。Quartz 自动配置允许没有 Scheduler，此时只创建空的 SchedulerManager；因此“有任务源码”不等于“任务已运行”。证据：S44、S45、S47、S63。

**[事实]** JobHandlerInvoker 有 `@DisallowConcurrentExecution`、执行前写日志、异步更新结果、失败重试与等待间隔；JobLogService 保存状态/结果并有清理方法。租户任务切面 parallelStream 遍历租户，逐租户捕获 Throwable，写入结果映射而不重新抛出该租户异常。证据：S46、S48、S49。

**[建议]** 复用后台调度管理与巡检/补偿触发外壳；玩家订单关单、支付查询、权益补发等必须另有幂等键、事务边界、可重入状态流转、持久失败记录与人工处理入口。同一 Job 的禁止并发不等于同一订单不会重复执行；逐租户异常被吞入字符串结果时，外层日志可能只反映整体执行完成，不能据“任务成功”判定每个租户业务都成功。等待间隔占用执行线程，失败规模扩大时也需评估。证据基础：S45、S46、S48、S49。

**[未验证]** Quartz job store、集群配置、实际任务定义、重启恢复、日志异步线程池、重试与告警行为未验证，不宣称已实现可靠消息、恰好一次处理或财务补偿闭环。
