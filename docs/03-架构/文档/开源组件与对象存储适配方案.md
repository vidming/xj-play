## 1. 开源优先的执行口径

优先满足功能、安全、维护与复用要求的开源社区方案，不因产品名称相似采用商业版。逐组件记录精确版本、源码、许可证、构建来源、维护状态和分发材料；顶层工程许可不能代表全部第三方依赖。

软件许可费、基础设施和运维成本分开列。无需购买软件许可不代表服务器、磁盘、外网、备份、证书管理与值守成本为零。未知费用继续标未知，不创建资源、不采购。

| 对象 | 当前处理 | 尚未确定的内容 |
| --- | --- | --- |
| 玩家端 | 沿用VB1的Nuxt／Node／pnpm验证组合 | 实际锁定依赖、构建与目标运行平台 |

## 3. 平台私有对象适配边界

以下为后端内部接口语义，不是新增对外HTTP接口，也不是已编写的Java实现：

| 内部动作 | 输入/结果语义 | 必须守住的边界 |
| --- | --- | --- |
| putImmutable | 服务端生成对象ID与内部key；有界数据流、长度、摘要；返回不可变ObjectRef | 重试不覆盖不同内容；冲突须查询和核验，不能无条件重PUT |
| statExact | 精确ObjectRef的元数据、实际长度与存储版本 | 缺失、无权限、依赖故障区分；未知不能当空文件或新对象 |
| openExact | 精确版本的有界可关闭流 | 调用前完成当前主体/run/作品/版本/权益检查；超限、中断或撤销及时终止 |
| deleteExact | 已获批清理计划及精确引用 | 查数据库/备份/未决操作引用窗口；记录结果；不能用不带版本的删除标记代替旧字节消退 |
| conditionalCreate / compareAndSwap | 限制日志候选需要的条件创建/更新与可核验回执 | 独立可选能力；未验证不启用，不能回退为普通PUT |

ObjectRef至少包含平台objectId、storageProfileRef、bucket逻辑角色、内部objectKey、存储versionId（OSF1要求非空且非字面`null`）、SHA-256、字节数和审核MIME。实际endpoint与凭据不放在公开API、游戏Manifest、日志或文档中。游戏只见resourceId及获准字节，不能传入桶名、任意key或URL。

ETag作为存储协议的条件比较令牌，不当作内容SHA-256。SDK返回的versionId、平台游戏versionId、业务revision是三个不同概念，不得互相替代。加密对象还需记录适用密钥版本及密文完整性信息，恢复需同时验证可解密性。

SDK流式接口不自动限制总字节、总内存或整个请求时长。适配器须设置长度/计数上限、请求与读取超时、并发及取消，确保异常时关闭或中止连接；实际行为需要在选定版本与目标服务端运行验证。

## 4. 对象分类与访问路径

| 逻辑角色 | 对象范围 | 写入、读取与清理原则 |
| --- | --- | --- |
| 上传隔离区 | 游戏包、封面和截图的未审文件 | 有权运营上传到服务端分配的精确位置；扫描和核摘要后才可被发布引用；未完成上传有独立清理规则 |
| 已发布游戏对象 | 不可变游戏包、公开引导源和受控正文 | 发布清单固定版本/摘要；公开分发流水线只复制审核为公开的内容；付费数据经Java可信读取 |
| 私人存档 | STAGED／REFERENCED等不透明存档对象 | 先持久对象再事务更新引用；云档归属/CAS由平台控制；无公开读链接 |
| 受限证据 | 必要渠道通知、审核与最小计划引用 | 独立权限和保留类别，不混进游戏资源；日志不包含正文或签名凭据 |
| 恢复材料 | 备份对象清单、制品、必要限制记录 | 与被恢复主库分离故障域与管理权限；不能只有另一个同盘目录 |

这些是逻辑角色，不是本轮已创建的桶。桶默认私有；公开站点图与游戏引导资源由受控发布/分发路径提供，SeaweedFS的管理、filer及volume内部入口不暴露为玩家入口。游戏独立来源隔离继续适用。

每个应用身份仅授予必要角色/前缀和动作；应用不得使用存储root身份。后台上传许可限精确对象、用途、尺寸、短有效期，并在完成时由服务端核实际字节与摘要；不能相信上传者填的hash就发布。配置值与密钥通过后续约定配置/密钥机制注入，本轮不读取或写入真实值。

## 5. 恢复、版本保留与清理

对象版本化、纠删码或副本不能单独证明已有独立备份；同一集群的另一个桶也不证明故障域独立。恢复需要精确数据库点、对象版本清单、制品和密钥相互一致，沿用RPO15分钟／RTO4小时的待验证目标。

按OSF1，私有桶首次写入前启用版本化，读取与删除使用精确非null存储versionId；删除标记仅隐藏当前版本时，旧版本仍须按保留政策处置。后台当前档＋上一恢复点不因对象版本化而增加玩家可见历史。不能给含个人存档的全部桶一刀切长期锁定，导致7日主资料清理与30日备份消退无法履行。

删除/撤权限制记录按SD2与平台、游戏表共用`xj_play`，业务限制及操作/事件在同一事务提交；恢复覆盖仍按[恢复规格第7节](部署资源与恢复规格.md#7-同库限制记录事务与恢复边界)取证。SeaweedFS负责正文、存档及约定对象，不承担独立限制日志；对象CAS继续禁用，同库日志也不能自证整库回滚后的限制尾部完整。

物理草案已增加`xj_storage_object`作为唯一精确存储引用，由`xj_resource.storage_object_id`、`xj_save_blob.storage_object_id`和可空的`xj_payment_notice.evidence_object_id`关联；另以`xj_storage_write`持久保存上传前计划及UNKNOWN查证状态。原重复摘要/长度改从对象表读取。证据对象保存原始body字节，明文摘要与通知`body_digest`一致，必要信封元信息另存最小字段，不将整体信封摘要混作body摘要。仅更新同一模型生成源、JSON、字典和图表，未执行DDL或迁移；公开API及17个游戏RPC不增加存储定位字段。详见下节的模型约束。

### 5.1 统一对象引用与并发边界

`xj_storage_object.public_id`对应内部ObjectRef的objectId；`storage_profile_ref`指向不可变配置版本，`bucket_role`映射实际私有桶，`object_key + storage_version_id`精确定位对象。配置仅放环境侧，不因更换endpoint就把旧引用指向另一批字节。`storage_version_id`为存储原样返回的二进制值，平台当前上限1024字节；超限拒绝、不截断，此上限是本项目约束，不冒称S3通用上限。

对象记录固定明文摘要/长度与实际上传字节摘要/长度。没有应用加密或变换时两者相等；有应用加密时还需密钥版本、算法及必要完整性元数据，并核验可解密性。MIME取审核结果。存储ETag仅作协议令牌。首期不以跨主体内容去重共享私人云档或通知证据，避免删除和授权相互耦合。

写入与引用顺序：

1. 先在主库事务持久`xj_storage_write`，固定可信执行主体、业务类型/作用域、稳定operationKey、预留objectId、不可变profile/角色/key及预期摘要/长度/MIME/加密引用，再发上传请求。同操作异计划拒绝，`idempotency.result_ref`可关联该上传动作，不单独承担完整计划。计划不是可读资源，也不是独立删除日志。
2. 核对版本化状态并上传。未取得可核验存储版本时，持久UNKNOWN，按原计划及受限元数据枚举查证精确候选版本，并逐个核验预期字节。候选记录有界，超量或无法证明完整时隔离，不截断丢证。不能读同key最新版本兜底，也不盲目覆盖原key；result_object_id为空不能被当作“没有上传字节”。
3. 按精确版本核实际上传长度/摘要，核明文长度/摘要、MIME及必要解密。锁原上传计划，在同一主库事务创建核验对象并关联唯一result_object_id，对象public_id等于预留objectId。只有通过后才能置为AVAILABLE；STAGED不向业务开放，计划与对象定位/元数据必须匹配。
4. 发布、存档提交或通知收件事务锁上传计划和对象行，验证原计划可信归属、AVAILABLE及角色后建立逻辑关联，不建物理外键。知道objectId或角色相同不代表有权绑定。存档同时按`save_head.revision`做业务CAS；对象存储版本并不代替CAS。
5. 对象定位、摘要、长度及加密元数据在核验后不可变。任何换字节或迁移都创建新计划/对象记录，经同样核验后切引用，并覆盖恢复窗口。

清理与新增引用锁同一上传计划/对象，统一顺序为业务守卫在前、上传计划及候选对象各按id排序在后。清理只锁计划/对象并以权威主端当前读检查已提交引用，不反向锁业务守卫，也不用旧事务快照判空；索引/隔离级别及死锁重试须在实现阶段验证。清理核资源、档头/冲突/保存操作、通知证据、在途上传重试以及保留备份清单，确定无合法引用且窗口已满足后改为DELETE_PENDING。此后新增引用拒绝；不能检查完引用便释放守卫再无条件删除。

放弃上传先改变计划状态和执行代次，禁止迟到完成建立新结果引用；但字段或租约本身不能阻止底层旧流继续写。须关闭/隔离旧写通路并确认在途请求、分片及迟到候选已查清，逐精确版本清理后才能将计划记COMPLETE。UNKNOWN、空结果关联ID、超时或租约过期均不自动等于可清孤儿。有效对象、未决上传及备份仍需归属/定位时保留最小计划；最后分类清理私人关联。

DELETE_PENDING只表示已排定清理；指定版本删除与查询核实最多先进入LOGICALLY_DELETED。PURGED要求全部适用副本、volume回收、缓存/快照与备份消退证据，具体门禁见[恢复规格6.2](部署资源与恢复规格.md#62-消退证据与清理状态)。未知结果保持待查证。最小清理回执先关联分类任务持久化，再按保留范围移除私人定位记录；不永久保存可回溯私人正文的对象索引。

## 9. 两种候选共同的验收条件

以下是产品比较的统一判据和后续实施验证要求，不是本轮已运行的测试，也不提前授权搭建验证环境。

| 场景 | 需要取得的证据 | 失败处理 |
| --- | --- | --- |
| 未配置身份、错误身份、匿名读取及越前缀访问 | 在最终启动配置、SDK和各内部入口下均按既定策略拒绝；应用身份不能管理全部存储 | 不能发布；不将外层桶私有或Java鉴权当作内部入口已封闭的证据 |
| 同key并发条件创建 | 两个不同摘要使用`If-None-Match:*`，不能均作为同一对象的成功创建；查询结果与回执一致 | 条件创建能力不验收，不允许静默回退普通PUT |
| 同版本并发条件更新 | 相同旧ETag的竞争者按预期串行，明确区分失败、不确定和已提交；覆盖多网关/元数据实例路径 | 条件更新能力不验收，独立限制日志CAS继续禁用 |
| 写成功后响应丢失、写途中依赖失联 | 使用稳定opId/objectId查询并核摘要；不能盲目覆盖、将未知当未写或误清理已引用数据 | 保留不确定状态，停止依赖该结果的发布/存档确认 |
| 精确版本读/删、删除标记及未完成上传 | 指定版本读到指定字节；精确清理不会删错当前版本；缺失与依赖错误不混同 | 不作为恢复可用版本；清理停止并查证，不凭HTTP成功推定全部副本字节已消退 |
| 游戏试玩、正式权益及撤权 | 同一资源ID在不同run/主体/版本下按实时服务端授权；撤权后拒绝后续新读取 | 不开放相关游戏；无存储URL或长期凭据下发 |
| 元数据与正文不同时点恢复 | 按业务恢复点逐个验证对象版本、长度、摘要和必要密钥；记录孤儿与缺失对象 | 缺对象的数据库点不算业务一致恢复点；恢复保持隔离 |
| 主资料7日、备份30日及旧版本消退 | 覆盖有效对象、历史版本、删除队列、底层回收、快照和独立备份的分类处置及到期证据 | 登记未满足项及责任；不能以对象列表不可见代替完成删除 |

条件写是能力开关，不能因最终选择某个产品就默认开启。平台存档业务revision仍由MySQL事务/CAS负责；它不等同于对对象key做CAS。限制记录现按用户SD2指示与平台/游戏表同放xj_play，业务限制/操作/事件/outbox同一事务提交；旧LR1独立库前提被覆盖。同库快照会回滚限制，缺完整恢复证据保持隔离，SeaweedFS日志CAS继续禁用，详见[恢复规格第7节](部署资源与恢复规格.md#7-同库限制记录事务与恢复边界)。

## 10. 比较后的资源核算口径

不使用无负载依据的CPU、内存、带宽或月费数字。至少分别记录活跃字节、需保留的历史版本、未完成上传/孤儿、待回收字节，以及独立备份容量。复制或纠删码的物理占用按最终部署实测或明确参数计算；不能把逻辑字节直接当磁盘采购量。

SeaweedFS已选方向与FM1确认的同库原版mysql/filemeta内部表例外，仍须单列filer元数据、master状态、volume数据及内部通信和备份责任；MinIO候选需单列源码构建、依赖安全更新、基础镜像与停止上游维护后的补丁责任。二者都须计入磁盘余量、恢复临时空间、私有代理出网、故障替代资源和值守条件。仅软件主项目许可无需另购，不代表上述项目为零。
