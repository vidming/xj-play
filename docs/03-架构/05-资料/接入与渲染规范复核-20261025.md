# 接入与渲染规范复核

V0.1；2026-10-25（Asia/Shanghai）；状态：一手资料核对与设计推导；不证明实现通过。

继承[20261024核查](官方规范核查-20261024.md)。本轮直接读取MDN、Vue官方和OpenAPI页面，HTTP均为200，并通过Context7查询Vue官方SSR说明。MySQL下列8.4链接本轮直接读取返回403，相关事实仅承接上轮核查，不能声称本轮再次读到手册正文；不替换本地依赖基线。

| 来源 | 本轮使用的有限事实 | 项目推导 |
| --- | --- | --- |
| [MDN postMessage](https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage) | 发送使用准确targetOrigin，接收检查来源和窗口；消息内容还需校验 | 入口校验后绑定当前frame/版本/频道，导航重建桥；频道随机值不当身份 |
| [Vue官方SSR说明](https://vuejs.org/guide/scaling-up/ssr)；Context7 `/websites/vuejs` 同主题 | SSR需要相应服务运行与缓存考虑；SSG为构建时静态内容，数据变更需要重建 | 首期少量作品建议公开目录/详情预渲染，搜索/身份/订单动态；SSR作为有发布频率/时效要求时的备选，未选框架 |
| [OpenAPI 3.1.1](https://spec.openapis.org/oas/v3.1.1.html) | 可描述HTTP路径、请求/响应和安全要求；定义不代替服务端授权实现 | 后续保存机器可读源；本轮接口目录不是全量OpenAPI，也不是已实现HTTP服务 |
| [MySQL 8.4锁定读](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html) | InnoDB事务内可使用锁定读协调并发，正确性依赖语句/索引与事务边界 | 同账号/作品守卫与来源固定顺序锁定、业务幂等；不持事务等待渠道网络，实际并发待测 |

本轮未调用支付/邮件/云供应商，没有最新价格、资质资格、资源容量或服务可得性结论。协议1.0、幂等策略与部署边界是本项目草案，不将自定义消息桥宣传为OAuth认证实现。

## SDK细化时的标准补查

2026-10-25继续核查资源传输，通用Web工具未返回可引用正文，改用只读HTTPS直接读取以下WHATWG一手规范，均HTTP200：

| 官方来源 | 读取到的有限事实 | 本项目使用及边界 |
| --- | --- | --- |
| [HTML Web messaging](https://html.spec.whatwg.org/multipage/web-messaging.html) | 发送机密信息不使用通配targetOrigin；transfer列表中的对象发生转移而非普通克隆，发送侧之后不可继续使用 | 入口握手验证准确来源；宿主发送独占ArrayBuffer，发送后不再复用该块 |
| [HTML Structured data](https://html.spec.whatwg.org/multipage/structured-data.html) | 结构化序列化与转移有不同规则；所有权转移不可逆且不幂等 | 原生buffer不假装JSON；失败重新读取/创建新块，不重复转移已转移buffer |

另调用Context7解析WHATWG HTML，结果只匹配W3C HTML仓库/引用站，没有匹配当前Living Standard，未用这些结果代替上述一手规范。标准是滚动文本，不构成目标浏览器版本测试。

资源索引、分块编号/ACK/取消、摘要校验、全局内存预算与宿主覆盖确认均为本项目的设计约束，**不是浏览器标准自动提供的业务协议**。静态Schema样本只能校验JSON形状；实际通道、buffer类型与转移、顺序/背压、摘要、隔离和并发仍未执行。
