## 1. 目标与平台边界

建设独立游戏商店与通用游戏接入平台“间隙PLAY”。初期重点支持剧本文字互动游戏，后续可以扩展其他类型和渠道。最终目标包括玩家前台、运营后台、后端能力、独立游戏接入、可交互高保真 Demo 及约定环境部署。

平台负责展示发现、账号身份、商品交易与权益、游戏启动、版本接入运营、安全隔离及通用数据交互。具体首期功能、商业模式及实现方式均待研究并确认。

游戏负责剧情、玩法、页面、规则与专有数据。不同游戏可以采用不同展示和交互方式，平台不统一剧情格式或引擎，不替代游戏开发，也不将现有表格阅读样例强加给其他游戏。

场景、章节标识可与平台商业对象映射，但不由平台接管游戏剧情。身份、购买与解锁状态不能仅凭前端传入取得信任。接入方式及多端含义在后续相应阶段论证。

## 5. Logo 与样例的准确用途

Logo 原 DOM 为 `间隙 <i>PLAY</i>`，PLAY 使用 `#df5a4e`，字重 800、字距 `-.05em`；继承系统字体。未找到独立矢量与固定字形资源，因此跨设备像素一致性尚未验证，不生成替代 Logo。

现有 HTML 中的配色、字距、间距等可作为视觉参考；其中固定游戏结果、单一玩法、示例商品和展示结构不构成平台约束。有更好设计时，在 UI 阶段提交对比；没有更好方案时可沿用其视觉。

高保真页的登录注册是提示，购买不创建订单；试玩页的 localStorage 只保存本机进度。两者都没有证明真实平台业务闭环。没有修改或扩展具体游戏。
