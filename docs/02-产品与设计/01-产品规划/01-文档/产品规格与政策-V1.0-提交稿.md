## 3. DP1 分类保留与注销清理（已确认）

### 3.1 时间起算与分类

AD1不可逆处理的玩家最终确认是`T_delete`；只提交申请、仍在撤回阶段不是已删除。最终确认后即时停止旧账号业务访问、撤会话，分类清理结果可查询。没有法定/其他核准必要性的数据应及时删除；下表是内部清理目标上限，**不能成为合法要求立即处理时的延迟理由**。

| 编号/数据类别 | 保留及到期动作 | 目的、限制与验收 |
| --- | --- | --- |
| POL-07 私人资料/云档 | T_delete后即时停止使用；可删除的在线私人资料、云档及上一恢复点目标7自然日内完成分类清理；没有依据不得继续用于运营/分析 | 凭据/会话立即失效；只保留清理状态的必要受限凭据，不保留完整剧情。7日非冷静期、不表示七天可恢复；新注册不继承 |
| POL-08 备份残留 | 已删除资料如暂时只能随备份轮转消退，隔离不供普通查询/分析，目标T_delete后30自然日内消退；恢复演练/灾备恢复先重放删除状态再开放业务 | 不因恢复把已注销账号/存档重新激活；具体备份实现留架构，不能靠“有备份”声称已永久全删 |
| POL-09 分析明细/汇总 | 可关联用户/会话的普通行为事件滚动30自然日，到期删除或真正匿名化；注销时不等30日，按POL-07处理；仅经不可逆匿名化的汇总建议保留3年用于区间比较 | 去标识不等于匿名。不能用分析日志保存邮箱、凭据、完整输入/存档；不把交易凭证或必要安全证据归入普通行为事件 |
| POL-10 交易/权益/售后与必要审计 | 有效履约期间保留最小权益/承诺/来源关系；交易及售后结案后的最小记录3年复核删除/匿名化；仍有效访问的必要映射继续受限保存；具体争议仅保留相关证据 | 3年是已采用的产品期限，适用性待核准，不声称全业务法定3年。每类登记处理目的、依据、起算、期限、访问人和到期动作；适用更严格要求时修订。不能因此保留全部私人资料或剧情 |

具体争议/法定义务例外必须有对象范围、依据、责任人、复核日；每90自然日复核，必要性结束后30自然日内完成相应清理目标，适用更短期限优先。不得用一个“有争议”标签冻结整个人全部数据。必要安全日志的法定类别和期限在安全方案中逐项核准；DP1不授权删除仍须依法保存的数据。

平台能处理平台持有的数据；不能承诺远程擦除玩家所有设备、第三方网页或游戏方独立持有的副本。游戏侧需要接收适用的删除/撤权结果并给实际处理回执，平台和游戏分别验收。

### 3.2 AD1与权益、恢复的联动

1. 在途付款/退款或争议需要处理时，说明具体阻塞及可查询进度；不能隐藏注销申请。可以先清理不受影响类别，保留事项单列。
2. 玩家最终确认前完整告知：私人云档将不可恢复、账号访问停止、购买不自动退款、必要交易记录受限保留。需要查阅/复制的可处理数据应提供受控申请路径，不把注销当作放弃法定请求。
3. 超期清理显示具体未完成类别/理由、负责人和下一复核，不回报“全部完成”。允许补偿重试，重复任务不误删其他账号；重新注册必须是新主体归属，不靠同邮箱恢复。
4. SS1的上一恢复点属于可清理的私人存档，不因叫“恢复点”无限保留；冲突来源已被平台接收的也计入分类清理。

DP0 未获选。正式公开前逐类核准适用性和资源可行性，本文件不是完整法律审查。真正匿名汇总按原获选政策保留“建议3年”的措辞；具体匿名化有效性须在架构及测试中验证。

## 4. SV1 售后、暂停与终止服务政策（已确认）

### POL-11 售后资格与人工处理

| 情况 | 规则与玩家出口 |
| --- | --- |
| 核实重复收款 | 每份真实付款分别核对，重复部分退回原付款来源；不要以重复通知虚构两次付款 |
| 已付款但未交付、作品与承诺不符、支持环境内无法运行 | 平台核实后给修复/补交付或退款方案；无法按承诺履行时不强迫接受仅平台余额；具体现金来源与访问结果书面可查 |
| 未启动、误购、不喜欢、已试玩/已游玩 | 均允许申请，不以已启动/某个自报时长一律拒绝；主观申请按RS1逐案考虑适用承诺、事实和异常重复，不新增无条件退购营销承诺 |
| 申请时间较久/缺证据 | 不设平台统一“超过X天自动拒绝”门槛；仍受理并核实适用规则，必要时要求补充订单/错误信息，不索要密码或完整剧情 |
| 仅撤升级/退原单/部分退款 | 继续RF1；核实每份可退现金及联动权益结果，不自动一键整组退款，不自行扣款补差；零补款无现金可退 |
| 拒绝/争议 | 给理由、事实、适用规则版本和再次核查入口；规则不能取代其他依法可用的争议途径；不写“平台拥有最终解释权” |

以自然小时作为内部服务目标：受理自动回执不算人工回应；**48小时内首次人工回应，持续处理中每72小时更新，7自然日内给出有依据的处理方案或明确缺项/查证状态**。七天不强迫未知支付/退款结案，也不是渠道到账期限。对超过30自然日仍未解决事项再次人工升级并给个案下一复核时刻，不能无限循环自动回复。

责任角色为“交易/用户支持处理者”和“复核负责人”，是未来职责，不代表已有两名员工或已配齐值班。实施计划需落实实际人员/代办、提醒和超时接手；无法覆盖这些目标应提出变更，不把目标当现有服务能力。

### POL-12 普通停售、安全暂停与永久停止

| 状态 | 处理与退出 |
| --- | --- |
| 普通停售 | 按已确认OP1停新售，保留有效已购访问、兼容版本和必要存档；不借改名转为永久关闭 |
| 安全/严重运行故障暂停 | 可以立即按影响范围暂停新售/新启动；显示受影响作品/范围、发现/处理时刻、支持入口与下次更新；不公开敏感攻击细节；不删除付款/存档 |
| 暂停中的进度 | 沿用48小时人工响应及72小时状态更新目标，不将未知恢复时间虚构为确定日期；玩家可申请售后，不必等暂停期满 |
| 恢复 | 通过约定的版本/权益/存档兼容与安全验证后恢复；首次重新进入核对当前权限，保存失败不假称恢复 |
| 计划永久停止游戏或平台 | 至少提前60自然日公告及触达受影响账号，停止新增受影响销售；保留查单/支持，给可执行的继续履约或退款方案；不能自动作废买断来源 |
| 无法继续履约 | 无等效且获玩家接受的继续方案时，按不能履行的商品范围核对尚未退还实付及来源，给逐项退款方案；不按未证实游玩时长强行折旧，不强制换成余额 |
| 紧急/依法要求立即停止 | 先采取必要措施，说明实际原因和后续可披露状态；60日预告不成为延迟保护的理由，仍保留历史/售后和适用数据请求出口 |

60日、48/72小时、7/30日是已确认的产品目标，不认定统一法定期限。涉及公开终止、实际退款/费用、购买资源或修改线上系统，后续仍需用户明确授权；确认政策不是执行这些操作的授权。

SV0 未获选；RS1/RF1/OP1 与本文件合并适用。
