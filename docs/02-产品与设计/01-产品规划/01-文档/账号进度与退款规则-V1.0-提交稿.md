- 关联：[PRD提交稿](间隙PLAY-产品需求文档-V1.0-提交稿.md)、[字段与统计](字段与统计规格-V1.0-提交稿.md)。

## 1. 已确认规则的组合

游客直接试玩 → 在付费边界可以返回/继续免费内容/购买 → 选择购买时登录 → 未验证邮箱先验证 → 回到原作品/商品，选择是否导入本机进度 → 核实报价、下单付款 → 核实权益 → 由游戏继续兼容进度。

进度导入可以先跳过，不能把“必须导入”作为下单条件。同样可以验证后先导入、继续试玩，再决定购买。取消登录、验证或购买仍可返回尚可试玩的部分。购买后进度不变成游戏内部的“已付证据”；游戏读取平台核实的访问范围。

G-A 的分支、G-B 的线索/链接/仿真网页都由独立游戏维护。一个收费场景可以跨多个页面，多个场景也可以共用页面；购买范围映射游戏标识，不按 URL 数量或点击次数收费。

## 2. 账号状态与动作权限（产品规则）

身份、邮箱验证、账号生命周期是三个维度，不合并成一个互斥状态。游戏运行/保存每次按当前权限判断；退出或过期后不继续展示私人云档。

| 状态/前提 | 浏览/试玩 | 新购/免费领取 | 私人订单与云档 | 退出/恢复路径 |
| --- | --- | --- | --- | --- |
| 游客 | 可浏览和直接试玩；仅游戏支持的本机进度 | 先登录并验证，不直接创建账号资产 | 不可读写账号私人数据 | 登录后返回原意图；不自动认领前一账号 |
| 已登录、未验证、正常 | 可以试玩和本机保存 | EV1 验证后才创建付费订单/完整免费授予 | 云档读写及游客导入均先验证；仅可访问本人账号设置/验证入口 | 重发/换有效链接；失败保留本机进度 |
| 已登录、已验证、正常 | 可以；正式内容仍需权益 | 商品可用、范围/价格核实后允许 | 只访问本人；云档还需游戏声明支持、版本兼容 | 正常保存/退出，切换账号清除前账号可见数据 |
| 会话过期 | 可重新进入独立游客试玩上下文，不沿用私人授权 | 先重新识别并重核报价/归属 | 过期上下文不能继续读写 | 保留支持的未上传进度；重登后确认目标账号，不自动覆盖 |
| 注销申请中（AD1已确认） | 仍可浏览/试玩 | 按AD1暂停新购/领取和新开正式运行，避免新增待处理资产 | 按AD1保留查单、售后、注销进度及撤回所需权限；云档冻结写入 | AD1 撤回后重新校验；不新增固定冷静期；不自动认定注销完成 |
| 注销处理/异常中（AD1已确认） | 可作为游客浏览/试玩，不能用旧账号继续私人操作 | 不新增该账号资产 | 仅本人经重新核验的进度/支持通道；不向游戏暴露待保留数据 | 重试/人工核实；异常不能回报“全部删除” |
| 已注销（AD1已确认） | 可作为游客浏览/试玩 | 如另建账号，按独立新账号处理 | 旧会话失效；不自动恢复旧权益或重绑原邮箱 | 有争议记录走受控人工核验，不以同邮箱自动认回 |

修改邮箱规则：先重新识别当前账号，再验证新邮箱；成功后撤销适用旧会话，资产仍属于原账号。新邮箱验证前原邮箱状态不被清空；失败/取消保留原登录方式。密码重置成功后撤旧会话；验证码、链接、密码不进分析事件。认证细节与供应商在架构阶段选定。

## 3. GP1 导入、恢复与冲突

| 场景 | 处理规则 | 保留/结果 |
| --- | --- | --- |
| 同设备存在兼容游客档，账号无档 | 展示作品、来源版本、当前账号；验证后由玩家选择导入或跳过 | 导入核实成功前来源保留，跳过不阻止购买 |
| 账号已有兼容云档 | 展示本机/云档来源、游戏版本和可信保存状态；由玩家选择继续哪份，不自动合并分支 | 选本机前先保留云档恢复来源；选云档不静默清除本机记录 |
| 玩家选择后另一端已更新云档 | 重核目标修订；暂停本次替换，重新展示冲突 | 不按设备时钟“取最新”；新旧可用来源保留 |
| 导入响应丢失 | 先核实同次操作是否成功，再决定重试 | 未核实显示待查证；不能以超时当失败后重复覆盖 |
| 数据不可读/游戏版本不兼容 | 说明实际原因，提供已声明支持的旧版/迁移/重开入口 | 不伪造恢复；不允许新版本强写旧档；重开需确认 |
| 切换账号 | 新账号重新验证/确认归属，不自动再次导入前账号私人数据 | 游客本机数据可以被玩家另行选择，不把它当购买来源 |
| 退款后存档含已走过的付费进度 | 保留进度与版本，当前能进入的范围重新核对权益 | 不凭存档继续越权，不因退款清空整份故事/线索记录 |
| G-B 多页面、前进后退、刷新 | 游戏维持本作品的连续状态和恢复点；平台侧继续关联同一账号/游戏及有效范围 | 导航本身不产生收费，不用商店页面强制重建游戏线索结构 |

### SS1：平台存档槽位（已确认）

- **SS1（已确认）**：每账号/作品 1 个当前继续位置 + 1 个上一份已确认恢复点；冲突处理期间保留参与冲突的双方来源，先解决再接受替换。恢复前确认、保留被替换的当前档，恢复后再次核对权益。上一恢复点只随下一次成功替换滚动，不承诺永久历史。未接收的第三份冲突数据保留在来源并提示暂缓上传，不能假报云保存。游戏可以在自己的存档内提供多周目或多个角色，不等于平台增加多槽。

SS2多命名槽没有获选；旧选项保留在前稿，不作为当前范围。每份存档1 MiB及分类保留/清理按已确认FS1/DP1。

导入/重开/手动恢复纳入同一保存操作核对，但保留独立动作类型。兼容映射由游戏负责，平台不解释剧情或将付费字段写进存档。

## 4. RF1 售后分类与现金、权益联动

受理、审核、退款执行和权益调整分别显示。申请不等于已批准；经核实的退款事实不能因为撤权失败而回写成退款失败。

| 分类 | 核对与处理 | 权益与记录 |
| --- | --- | --- |
| 普通买断/章节/场景退款 | 核对原付款、剩余可退额、范围、申请原因和适用规则；人工给结论/理由 | 获准且退款核实后调整对应来源；其他有效来源仍可访问 |
| RF1 仅撤升级 | 只退该次新增实付，核实成功后撤该次买断授予、释放抵扣关联 | 原仍有效章节/场景保留；不能退原单现金又把来源当足额抵扣 |
| 原单曾参与有效升级 | 进入关联审核，说明受影响的升级/剩余范围；给出可执行的联动处理结论再推进 | 未解决来源变化前不独立撤原单后留无足额来源的买断，也不自动扣款补差 |
| 部分退款/多个范围重叠 | 核实具体退款额和对应访问结果，缺少明确范围时退回人工补方案 | 金额不自动等于一个章节；不得任意按比例删除剧情或其他权益 |
| 零补款升级/完整免费授予 | 作为撤销或权益问题受理，不产生现金退款 | 保留原授权来源与变更留痕，不生成假退款渠道记录 |
| 付款结果未知/重复实收 | 先查证每份真实现金事实；核实的重复实收单独处理 | 不从重复按钮或通知推断多笔钱；超额收款不能吞掉 |
| 退款失败/未知 | 区分明确失败与查证中，重试前核对已退累计与在途请求 | 不重复发起超额退款；是否安全暂停另有依据，不把未知当已撤权 |
| 已退款、撤权处理异常 | 退款金额按真实成功记录，权益处理显示异常并重试/人工收敛 | FN1 计入退款事实；不为平账伪造撤权成功或倒改退款事实 |
| 游戏安全暂停/不可恢复 | 说明影响范围，关联查单、修复与售后；停新售和暂停运行分开 | 不删除存档/付款证据，永久停止按已确认SV1/POL-12处理 |

审核结论包含：原因分类、核实事实、退款额/币种、关联付款及升级、处理前后范围、适用规则版本、操作者/时间、拒绝理由或补充材料、玩家可查询结果。材料仅收故障和订单所需，不能要求密码或完整剧情存档。

### RS1：普通售后受理方向（已确认）

- **RS1（已确认）**：统一人工受理，区分“重复收款/无法交付/内容与承诺不符”等客观问题与“不喜欢/误购”等主观申请。逐案给核实结果及理由；不承诺主观申请一律可退，也不一律拒绝。修复、补交付或退款方案需可查，复杂来源按 RF1 联动。此为产品受理流程，不认定任何法定资格、免责或固定天数。

具体资格、时限与暂停/终止政策见已确认SV1，不从RS1推出无条件退购。

## 5. AD1：账号注销流程（已确认）

- **AD1（已确认）**：重新识别 → 展示权益/存档/订单影响并二次确认 → 登记注销申请 → 人工核对在途交易/售后 → 玩家收到处理范围说明后再次确认开始不可逆处理。最后确认前可撤回；不增加固定冷静天数。申请期间暂停新增资产、云档写入和新开正式运行，保留查单、售后与撤回入口。存在在途事项应说明阻塞原因、处理责任及状态，不能无期限隐藏申请。

AD2固定7日冷静期没有获选。分类清理的7日目标不是冷静期、不是可恢复窗口，不得混淆。

分类处理规则：登录凭据和私人资料停止使用并按DP1政策删除/去关联；云档及历史恢复点按已确认范围处理；订单、退款、权益变更和必要审计分别限制访问并说明保留依据。保留清单、具体期限与备份消退按DP1/POL-07–10执行，重新注册不继承旧账号归属；本轮不授权真实注销。购买不自动退款；注销不转移资产；不能把“玩家点了注销”当作售后问题全部解决。

## 6. LC1：首期语言与币种（已确认）

- **LC1（已确认）**：平台首期简体中文、CNY 单币种，价格以元显示、金额按分精确核对；不同游戏单独声明内容语言。减少翻译、混币报价、退款与统计复杂度，不等于选定支付渠道或支付资质已经具备。

不增加平台双语或混币；金额上限999999分、展示报价10分钟按FS1，变化仍重核。
